# WOT 게임 로직 레이어 구조 현황

`docs/archive/게임로직_이식_20260811/`(2026-08-11 사이클)에서 이식한 아키텍처 뼈대와, `WOT-master`에 아직 남아있어 이식되지 않은 부분을 한눈에 보기 위한 영구 참조 문서.
`docs/algorithm/`, `docs/architecture/platform_graphics_projects.md`와 동일하게 사이클 종료 후에도 archive하지 않고 이 위치에 보관하며, 새 사이클이 진행되면 이 문서를 갱신한다.
사용자가 나중에 `WOT-master`의 구조를 다시 살펴보고 다음 작업을 정할 때 출발점으로 쓰기 위한 문서다.

---

## 지금 리팩토링 프로젝트(`src/`)에 있는 것

이식 대상이었던 4개 영역(GameManager/Objects/Scene/Algorith) 중, 이번 사이클은 **"씬 전환·생명주기 뼈대"만** 옮겼다. 전부 `src/projects/game/`에 있다.

| 클래스 | 원본과의 관계 | 책임 |
|---|---|---|
| `GameManager` | 이름만 원본과 동일, 책임은 다름 | 조립 지점(composition root) — `SceneManager`를 소유하고 `PrototypeScene` 하나를 등록·활성화. 원본과 달리 Device/Audio/Font/ImGui 초기화나 자체 렌더 루프를 갖지 않는다. |
| `SceneManager` | 이름만 원본과 동일, 싱글턴 아님 | 씬을 key로 등록(`Create`)/활성화(`Add`)/비활성화(`Remove`), 활성 씬들의 `Update` 위임. |
| `Scene`(추상) | `PreRender`/`Render`/`PostRender`/`GUIRender` 없음 | `Start`/`Update(dt)`/`End` 생명주기 + 자신이 만든 Entity 목록 보유(`GetEntities()`). |
| `PrototypeScene` | `WOT-master`의 `TestScene`을 대체 | 원본 `TestScene`의 tank 모델/충돌 디테일 없이, 기존 `InstanceUpdateWorker`의 격자+bob+회전 데모를 Scene/Entity 경유로 재현. |
| `TransformComponent` | 신규(원본에 대응 없음) | `platform/entity_component::ComponentBase`를 상속한 최소 데이터 Component. Entity 하나당 위치/회전/스케일만 담음. |
| `SceneSnapshotBuilder` | 신규(원본에 대응 없음) | 활성 씬들의 `TransformComponent`를 모아 `graphics/renderer::InstanceSnapshot`으로 변환. |

**엔진/렌더 스레드 분리와의 통합**: `SceneManager`+`Scene::Update()`는 `src/projects/engine/InstanceUpdateWorker`(engine 스레드) 안에서 돈다. 원본처럼 자체 D3D 렌더 호출을 하지 않고, `SceneSnapshotBuilder`가 만든 `InstanceSnapshot`을 `DoubleBufferPublisher`로 렌더 스레드에 넘긴다. `main.cpp`/`IRenderer`는 변경되지 않았다.

## `WOT-master`에만 있고 아직 이식 안 된 것

- `Objects/Character`(Naruto, Zombie), `Objects/Particle`(Particle/Rain/Spark/Sprite/Trail), `Objects/PostEffect`(Outline), `Objects/UI`(ProgressBar, UIImage), `Objects/Landscape`(Terrain, TerrainEditor) — 전부 미이식.
- `Algorith/`(AStar/Heap/Node/Observer, 경로탐색) — 미이식.
- `Scene/WOT/TestScene`의 실제 내용(Tank01_Body/Gun/Turret 3개 Model, BoxCollider 2개, Outline/Trail/RenderTarget) — `PrototypeScene`은 이 중 아무것도 옮기지 않았다. 뼈대만 검증했다.
- `Scene/WOT/WOT.cpp/h` — 원본에서도 빈 스텁이었고, 리팩토링 프로젝트에도 아직 대응하는 게 없다. 실제 게임 진입 씬으로 채워야 할 자리.
- `Scene/` 아래 데모/튜토리얼 씬 12개(AStarScene, BillboardScene, CollisionScene, GridScene, InstancingScene, LightScene, ModelAnimatorScene, ModelExporterScene, ModelInstancingScene, ModelRenderScene, ParticleScene, TerrainEditorScene, TerrainScene, TutorialScene) — 2026-08-11 사이클 브레인스토밍에서 이식 대상 제외로 확정됨(포트폴리오 목표와 무관한 데모).

## 다음에 구조를 다시 잡아야 할 수도 있는 지점 (2026-08-11 사이클 Refactor Inspection에서 보류된 항목)

- **Entity 제거(수명주기) 미설계** — `Scene`은 Entity를 만드는 경로(`CreateEntity()`)만 있고 지우는 경로가 없다. 전차 파괴 등으로 Entity를 실제로 제거해야 하는 기능이 생기면, `Scene::m_entities`(열거용 목록)와 `EntityManager`(소유) 두 자료구조를 동시에 갱신하는 API를 설계해야 한다.
- **`GameManager`의 씬 하드코딩** — 현재 씬을 정확히 1개(`"Prototype"`)만 등록한다. 로딩 화면 → 실제 게임플레이 전환처럼 씬이 여러 개 필요해지면 `GameManager`가 씬 목록/설정을 받는 형태로 바뀌어야 한다.
- **얇은 데이터/기반 타입의 테스트 관례** — `TransformComponent`/`Scene`처럼 얇은 타입에 전용 테스트를 둘지, 지금처럼 소비자 테스트로만 간접 검증할지는 아직 프로젝트 차원에서 확정되지 않았다(`ComponentBase`도 같은 상태).
