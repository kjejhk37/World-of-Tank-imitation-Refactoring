# Strategy: ImGui 기반 기본 UI 프레임워크

## 적용 방식 요약

브레인스토밍에서 확정된 설계를 아래 순서로 코드에 반영한다 — ImGui 의존성 확보 → `IUiManager` 인터페이스 → 백엔드별 구현체(DX9/DX11/DX12) → `IRenderer`/`Win32Window` 확장 → 각 렌더러 배선 → `main.cpp` 배선 → 빌드/테스트.

- ImGui는 DX9/11/12 세 백엔드 모두에 연결을 시도한다. DX12(SRV 디스크립터 힙 필요)가 구현 중 실제로 막히면 `ImGuiManagerDX12`를 구조만 갖춘 상태로 남기고 커밋 리포트에 `[DEFERRED]`로 명시한다(사용자 사전 승인된 폴백) — **결과: 폴백 미발동, 세 백엔드 모두 완전히 구현됨.**
- `src/ui/IUiManager.h` + 백엔드별 폴더(`src/ui/directx9/`, `directx11/`, `directx12/`) — 렌더러 폴더 구조와 동일 패턴.
- `Initialize`는 `IUiManager`에 넣지 않는다(백엔드마다 파라미터가 완전히 다름) — 각 구현체 생성자가 자신에게 필요한 DX 타입을 직접 받는다.
- 각 `DirectX9/11/12Renderer`가 자기 짝 `ImGuiManagerDXn`을 멤버로 소유 — ImGui 백엔드는 `config.renderer` 선택에 자동 종속되고, 별도 config 필드는 추가하지 않는다.
- `IRenderer`에 `HandleUiMessage(HWND,UINT,WPARAM,LPARAM)` 추가, `Win32Window`에 `SetMessageHook` 범용 콜백 추가 — `Win32Window`는 여전히 ImGui/`IRenderer`를 모른다.
- 검증은 **빌드까지만** — 컴파일/링크/`ctest` 통과 + `--renderer=directx9/11/12` 각각 크래시 없이 실행. 시각적 위젯/데모 없음, `AppConfig` 변경 없음.

## 구현 체크리스트

### 1. ImGui 의존성 확보

- [x] GitHub(`ocornut/imgui`)에서 최신 안정 릴리스 태그 확인(`docking` 브랜치 아님) 후 `CMakeLists.txt`에 `FetchContent_Declare(imgui URL .../archive/refs/tags/<확인된 태그>.zip ...)` 추가 — `v1.92.8`(2026-05-12 릴리스)로 고정
- [x] `FetchContent_MakeAvailable(imgui)` 호출 — ImGui 저장소에는 소비자용 CMakeLists.txt가 없어 `add_subdirectory` 없이 소스만 받아온다(population-only, `nlohmann_json`/`googletest`와 다른 지점)
- [x] `app_lib`에 `${imgui_SOURCE_DIR}/imgui.cpp`, `imgui_draw.cpp`, `imgui_tables.cpp`, `imgui_widgets.cpp`, `backends/imgui_impl_win32.cpp`, `backends/imgui_impl_dx9.cpp`, `backends/imgui_impl_dx11.cpp`, `backends/imgui_impl_dx12.cpp` 추가
- [x] `target_include_directories(app_lib PRIVATE ${imgui_SOURCE_DIR} ${imgui_SOURCE_DIR}/backends)` — `main`/`tests`의 include 경로에 ImGui 헤더가 노출되지 않게 격리

### 2. `IUiManager` 인터페이스

- [x] `src/ui/IUiManager.h` 작성 — `virtual void NewFrame() = 0`, `virtual void Render() = 0`, `virtual void Shutdown() = 0`, `virtual bool HandleWin32Message(HWND, UINT, WPARAM, LPARAM) = 0`, ImGui 타입 노출 없음

### 3. `ImGuiManagerDX9`

- [x] `src/ui/directx9/ImGuiManagerDX9.h/.cpp` 작성
- [x] 생성자(`HWND windowHandle, IDirect3DDevice9* device`): `ImGui::CreateContext()` → `ImGui_ImplWin32_Init(windowHandle)` → `ImGui_ImplDX9_Init(device)`
- [x] `NewFrame()`: `ImGui_ImplDX9_NewFrame()` → `ImGui_ImplWin32_NewFrame()` → `ImGui::NewFrame()`
- [x] `Render()`: `ImGui::Render()` → `ImGui_ImplDX9_RenderDrawData(ImGui::GetDrawData())`
- [x] `Shutdown()`: `ImGui_ImplDX9_Shutdown()` → `ImGui_ImplWin32_Shutdown()` → `ImGui::DestroyContext()`
- [x] `HandleWin32Message(...)`: `ImGui_ImplWin32_WndProcHandler(...) != 0` 반환
- [x] 단위 테스트: 실제(HAL) `IDirect3DDevice9`로 생성 후 `NewFrame`/`Render`/`Shutdown`이 크래시 없이 동작하는지 검증(`DirectX9RendererTest`와 동일 스모크 테스트 스타일)

### 4. `ImGuiManagerDX11`

- [x] `src/ui/directx11/ImGuiManagerDX11.h/.cpp` 작성 — DX9와 동일 패턴, `ImGui_ImplDX11_Init(device, context)`
- [x] `NewFrame`/`Render`/`Shutdown`/`HandleWin32Message` DX9와 동일 구조(`ImGui_ImplDX11_*` 호출로 대체)
- [x] 단위 테스트: WARP 디바이스로 생성 후 크래시 없이 동작 검증(`DirectX11RendererTest`와 동일 스타일, `forceWarp` 패턴 재사용)

### 5. `ImGuiManagerDX12`

- [x] `src/ui/directx12/ImGuiManagerDX12.h/.cpp` 작성
- [x] ImGui 폰트 텍스처용 SRV 디스크립터 힙(`ID3D12DescriptorHeap`, `D3D12_DESCRIPTOR_HEAP_TYPE_CBV_SRV_UAV`, 디스크립터 1개, `D3D12_DESCRIPTOR_HEAP_FLAG_SHADER_VISIBLE`)을 이 클래스 내부에 소유(`DirectX12Renderer`의 기존 RTV 힙과는 별개)
- [x] 생성자(`HWND, ID3D12Device*, ID3D12CommandQueue*, int numFramesInFlight, DXGI_FORMAT rtvFormat`): `ImGui_ImplWin32_Init` → SRV 힙 생성 → `ImGui_ImplDX12_Init(&initInfo)`
  - **구현 중 변경**: v1.92.8 기준 `ImGui_ImplDX12_Init`은 계획 당시 가정한 "개별 인자(device, numFrames, rtvFormat, srvHeap, cpuHandle, gpuHandle)" 시그니처가 아니라 `ImGui_ImplDX12_InitInfo` 구조체 하나를 받는 API로 바뀌어 있었다. 이 구조체는 `CommandQueue`와 `SrvDescriptorAllocFn`/`SrvDescriptorFreeFn` 콜백(디스크립터 동적 할당/반환 훅)을 추가로 요구해, 생성자 시그니처에 `ID3D12CommandQueue*`를 추가하고, 힙에 디스크립터가 1개뿐이므로(폰트 아틀라스 전용) 그 슬롯을 그대로 내주는 최소 콜백 두 개를 익명 네임스페이스에 구현해 대응함.
- [x] DX12는 draw call 기록에 커맨드 리스트가 필요해 `IUiManager::Render()`(무인자)로는 표현 불가 — `ImGuiManagerDX12`에 인터페이스 밖 전용 메서드 `void RenderWithCommandList(ID3D12GraphicsCommandList* commandList)`를 추가로 노출하고, `DirectX12Renderer`는 `IUiManager*`가 아니라 구체 타입 `ImGuiManagerDX12`로 직접 호출한다
- [x] `Shutdown()`: `ImGui_ImplDX12_Shutdown()` → `ImGui_ImplWin32_Shutdown()` → `ImGui::DestroyContext()` (SRV 힙은 ComPtr 소멸에 위임)
- [x] 단위 테스트: WARP 디바이스로 생성 후 크래시 없이 동작 검증(`DirectX12RendererTest`와 동일 스타일)
  - **폴백 미발동**: SRV 힙/디스크립터 관리가 우려했던 것만큼 복잡하지 않아(디스크립터 1개 고정 할당으로 충분) DX12도 다른 두 백엔드와 동일하게 완전히 구현됨 — `[DEFERRED]` 폴백은 사용하지 않음.

### 6. `IRenderer` 확장

- [x] `IRenderer.h`에 `virtual bool HandleUiMessage(HWND, UINT, WPARAM, LPARAM) = 0;` 추가
- [x] `OpenGLRenderer`: `return false;`만 구현(기존 스텁 패턴과 동일)

### 7. `Win32Window::SetMessageHook`

- [x] `Win32Window.h`에 `void SetMessageHook(std::function<bool(HWND, UINT, WPARAM, LPARAM)> hook);` 추가
- [x] `Win32Window.cpp`의 `WndProc` 맨 앞에서 훅 호출 — `true` 반환 시 그 자리에서 `return true`(ImGui 공식 예제와 동일 관용구)
- [x] 단위 테스트: 훅을 등록하면 임의 메시지에 대해 훅이 호출되는지, 훅이 `false`를 반환(혹은 미등록)하면 기존 `WM_SIZE`/`WM_DESTROY` 처리가 그대로 동작하는지 검증

### 8. 각 렌더러 배선

- [x] `DirectX9Renderer`: `std::unique_ptr<ImGuiManagerDX9> m_uiManager` 추가. `Initialize` 성공 후 생성. `RenderFrame`에서 `Clear` 전에 `NewFrame()`, `BeginScene`/`EndScene` 사이에 `Render()`(DX9는 draw call이 BeginScene 블록 안에 있어야 함). `Shutdown`에서 디바이스 해제 전에 `Shutdown()`. `HandleUiMessage`는 위임.
- [x] `DirectX11Renderer`: 동일 패턴, `ImGuiManagerDX11(windowHandle, m_device.Get(), m_context.Get())` — `ClearRenderTargetView` 이후 `Present` 이전에 `Render()`
- [x] `DirectX12Renderer`: `ImGuiManagerDX12(windowHandle, m_device.Get(), m_commandQueue.Get(), kBackBufferCount, DXGI_FORMAT_R8G8B8A8_UNORM)`로 생성. 커맨드 리스트 기록 구간(`ClearRenderTargetView` 이후, Present용 리소스 배리어 이전)에서 `commandList->OMSetRenderTargets(...)`(기존 코드에 없던 호출 — draw call이 실제로 그려질 대상을 바인딩하기 위해 추가) 후 `m_uiManager->RenderWithCommandList(commandList)` 호출
- [x] 각 렌더러의 클래스 주석(Notes)에 ImGui 연동 사실 추가

### 9. `main.cpp` 배선

- [x] `renderer->Initialize(...)` 성공 이후 `window->SetMessageHook([&renderer](HWND h, UINT m, WPARAM w, LPARAM l) { return renderer->HandleUiMessage(h, m, w, l); });` 추가

## 최종 승인 및 검증 기준

- CMake로 `main`, `tests` 타겟이 모두 정상 컴파일·링크된다.
- `tests` 타겟의 모든 케이스(`ImGuiManagerDX9/11/12`, `Win32Window`의 `SetMessageHook` 포함)가 통과한다.
- `main.exe --renderer=directx9`, `--renderer=directx11`, `--renderer=directx12` 각각 실행 시 크래시 없이 창이 뜬다(수동 확인, 시각적 ImGui 콘텐츠는 없음).
- `<imgui_impl_dx9.h>`/`<imgui_impl_dx11.h>`/`<imgui_impl_dx12.h>`를 동시에 include하는 파일이 없다(grep으로 확인).
- ImGui 관련 헤더(`imgui.h`, `imgui_impl_*.h`)는 `src/ui/` 하위 구현 파일에만 존재하고, `main`/`tests`의 include 경로 상으로 노출되지 않는다.
- `ImGuiManagerDX9`/`DX11`/`DX12`/`IUiManager`가 각각 단일 책임만 가지는지 코드 리뷰로 확인한다(SRP).
- `config.renderer` 값 하나로 사용되는 ImGui 백엔드까지 자동으로 결정되며, 별도 ImGui 관련 config 필드가 존재하지 않는다.
- 신규 작성된 모든 함수/클래스에 CLAUDE.md 주석 규칙(Author / 설명 / Input / Output / Notes / Date)이 반영되어 있다.
- (DX12가 폴백된 경우) 커밋 리포트에 `[DEFERRED]`로 명시되고, 향후 별도 태스크로 이어갈 수 있는 구조가 남아있다.
