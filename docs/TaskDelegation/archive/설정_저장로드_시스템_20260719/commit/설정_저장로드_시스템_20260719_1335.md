# Notes

- `SqliteDataStore`는 의도적으로 스텁 상태 — 실제 DB(SQLite 후보) 연동은 저장 데이터 규모가 커져 전환이 필요해지는 시점에 별도 Task + `dependency_eval`로 진행.
- `SaveLoadManager::SaveAsync`는 시그니처만 제공하고 내부적으로 동기 `Save`에 위임 — 실제 비동기(멀티스레드) 구현은 별도 Task 범위.
- Save 데이터 범위는 메타 진행 정보(예: `PlayerProgress`의 재화/해금 탱크 목록) 수준으로 한정 — 인게임 미드매치 상태 저장은 엔티티/월드 시스템 도입 이후 별도 Task.
- 로컬 상수(1~2개, `RendererBackendParser.cpp`/`main.cpp`)는 "500줄 또는 상수 5개 초과 시 별도 헤더로 분리"라는 기준을 파일 상단 주석으로 남겨둠 — 이후 파일이 커지면 이 기준에 따라 분리.
- `config.json`은 저장소에 샘플 파일을 커밋하지 않음 — 파일이 없을 때도 하드코딩 기본값으로 정상 동작하는 것을 테스트/수동 검증으로 확인했기 때문에, 실제 필요 시 사용자가 직접 생성하거나 이후 Task에서 샘플을 제공.
