# Commit: Component 패턴 기본 구조 구현

## 구현 결과

- `src/entity_component/UniqueId.h` — `UniqueIdGenerator<IdType>`, `std::atomic<uint64_t>` 기반 원자적 ID 발급기.
- `src/entity_component/EntityId.h`, `ComponentId.h` — `enum class` 기반 opaque 강한 ID 타입.
- `src/entity_component/IComponent.h` — `GetId() const -> ComponentId` 최소 인터페이스.
- `src/entity_component/ComponentBase.h` — ID 자동 발급 편의 기반 클래스.
- `src/entity_component/IEntity.h` — 인터페이스(`GetId`/`AddComponent`/`RemoveComponent`/`FindComponent`/`FindComponents`) + free template `AddComponent<T>`/`GetComponent<T>`/`GetComponents<T>`.
- `src/entity_component/Entity.h`/`.cpp` — `IEntity` 구현체. `ComponentId` 키 소유권 map + `type_index` 보조 인덱스로 같은 타입 다중 보유 지원.
- `src/entity_component/EntityManager.h`/`.cpp` — Entity 생성/조회/파괴 전담.
- `CMakeLists.txt`: `app_lib`에 `Entity.cpp`/`EntityManager.cpp` 2개, `tests`에 `EntityTest.cpp`/`EntityManagerTest.cpp` 2개 추가.
- `tests/EntityTest.cpp`(10개) / `tests/EntityManagerTest.cpp`(5개) — AddComponent/GetComponent 단일·다중 조회, 타입 간 비간섭, RemoveComponent(개별/전체/미존재 id), Entity 소멸 시 Component 연쇄 소멸(RAII), Entity/Component ID 유일성, EntityManager 생성/조회/파괴 전 케이스.

## 브레인스토밍 확정 사항 반영

- 이름을 "ECS"가 아니라 **"Component 패턴"**으로 명명 — Unity Classic(GameObject/Component)·Unreal
  Classic(Actor/ActorComponent)과 동일 계열이며, Unity DOTS/Unreal Mass 같은 데이터 지향 ECS와는 다른
  세대임을 확인한 브레인스토밍 결론에 따름(`docs/brainstorming/Component_패턴_기본구조_20260722_2217.md` Details 8).
- `ComponentRegistry`(전역 Component 색인)는 만들지 않음 — 실제 호출 패턴이 항상 Entity를 먼저 거치므로 불필요.
- Entity 간 계층(부모-자식) 구조, System은 이번 범위에서 제외 — 후속 사이클로 분리.
- 멀티스레드: ID 발급만 `std::atomic`, 컨테이너 자체는 단일 스레드 전제(주석 명시).

## 코드 리뷰 결과 반영 (`../review/Component_패턴_기본구조_20260722_2307.md`)

Stage 1에서 발견된 5건 전부 이번 사이클 개발 범위 안이라 즉시 해소함 (전부 `[RESOLVED]`).

- `GetComponent<T>()`/`GetComponents<T>()`의 `static_cast` → `dynamic_cast`로 교체(방어적 타입 검증).
- `Entity::AddComponent`에 null 컴포넌트 방어 `assert` 추가.
- `Entity.h`/`EntityManager.h`에 `<memory>` 명시적 include 추가.
- `Entity.cpp`에 `<typeindex>` 명시적 include 추가.
- 타입의 마지막 Component 제거 시 보조 인덱스 정리 분기를 검증하는 테스트 추가.
