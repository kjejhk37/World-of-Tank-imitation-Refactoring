# Code Review: DirectX 초기 설정 및 빈 화면 출력

## Stage 1 — Quality Inspection

### 즉시 해결 가능 (이번 Task 범위 내)

- `[RESOLVED]` `[MEDIUM]` `Win32Window` 생성자가 창 생성 실패 시 `std::runtime_error`를 던진다.
  - `main.cpp`는 이 예외를 잡지 않는다.
  - 창 생성이 실패하면(리소스 부족 등) 사용자에게 아무 메시지 없이 그냥 크래시한다.
  - 같은 `main.cpp` 안에서 argv 파싱 실패(`std::invalid_argument`)는 이미 `try/catch`로 잡아 메시지를 출력하는데, 창 생성 실패만 이 패턴을 따르지 않아 비대칭이다.
  - **[해결 방안]**
    - `Win32Window window(...)` 생성 부분을 기존 argv 파싱과 같은 `try/catch` 블록으로 감싼다.
    - `std::runtime_error`를 잡아 `stderr`에 메시지를 출력하고 종료 코드 1로 반환한다.
  - **[처리 결과]** `main.cpp`에서 `Win32Window`를 `std::unique_ptr`로 만들고 생성 부분을 `try/catch`로 감쌈 — 예외 시 메시지 출력 후 종료 코드 1 반환.

- `[RESOLVED]` `[MEDIUM]` `RendererFactory::Create`가 `nullptr`을 반환할 가능성에 대해 `main.cpp`가 무방비하다.
  - `RendererBackend`에 새 값이 추가되고 `RendererFactory.cpp`의 `switch`에 case를 깜빡 추가하지 않으면 `Create`가 `nullptr`을 반환한다.
  - `main.cpp`는 반환값을 null 체크 없이 바로 `renderer->Initialize(...)`로 역참조한다.
  - 지금 당장은 4개 값 모두 case가 있어 발생하지 않지만, 이번 사이클에서 이미 enum에 값 2개(DirectX9/12)를 새로 추가한 것처럼 향후에도 값이 늘어날 가능성이 있는 지점이다.
  - **[해결 방안]**
    - `main.cpp`에서 `renderer`가 `nullptr`이면 에러 메시지를 출력하고 종료 코드 1로 반환하는 가드를 추가한다.
  - **[처리 결과]** `main.cpp`에 `if (!renderer) { ... return 1; }` 가드 추가.

- `[RESOLVED]` `[MEDIUM]` `OnResize` 계열 메서드에 대한 자동화된 단위 테스트가 없다.
  - `DirectX9Renderer::OnResize`/`DirectX11Renderer::OnResize`/`DirectX12Renderer::OnResize` 모두 수동으로만(`SetWindowPos`로 프로그램적 리사이즈 후 프로세스 생존 확인) 검증했다.
  - 회귀가 생겨도 `ctest`로는 잡히지 않는다.
  - **[해결 방안]**
    - 각 렌더러 테스트에 `Initialize` 후 `OnResize`를 다른 크기로 호출하고, 이어서 `RenderFrame`을 호출해도 크래시 없이 동작하는지 검증하는 케이스를 추가한다.
    - `OnResize(0, 0)`(최소화 시나리오)을 호출해도 예외/크래시가 없는지 검증하는 케이스도 추가한다.
  - **[처리 결과]** DX9/11/12 테스트 각각에 `SurvivesResizeAndRenderFrame` 케이스 추가(정상 리사이즈 + `OnResize(0,0)` 둘 다 검증).

- `[RESOLVED]` `[LOW]` `Win32Window`의 전체화면(borderless fullscreen) 생성 결과에 대한 자동화된 검증이 없다.
  - `fullscreen=true`로 생성했을 때 실제로 `WS_POPUP` 스타일과 모니터 해상도로 만들어지는지는 수동 스크린샷 확인으로만 검증했다(창 rect가 화면 해상도와 정확히 일치함을 확인).
  - **[해결 방안]**
    - `Win32WindowTest`에 `fullscreen=true`로 생성한 뒤 `GetWindowRect`로 얻은 크기가 `GetSystemMetrics(SM_CXSCREEN)`/`SM_CYSCREEN`과 일치하는지 검증하는 케이스를 추가한다.
  - **[처리 결과]** `Win32WindowTest::FullscreenClientSizeMatchesScreenResolution` 추가 — `ClientWidth()`/`ClientHeight()`가 `SM_CXSCREEN`/`SM_CYSCREEN`과 일치함을 검증.

- `[RESOLVED]` `[LOW]` **[사용자 제안]** `src/renderer/`가 공용 선택 인프라(`IRenderer`/`RendererBackend`/`RendererBackendParser`/`RendererFactory`)와 백엔드별 구현체(DirectX9/11/12/OpenGL) 8개 파일이 한 디렉토리에 평평하게 섞여 있다.
  - 지금은 각 백엔드가 2개 파일(.h/.cpp)뿐이지만, 다음 사이클(실제 렌더링 기능)에서 백엔드별 파일이 더 늘어날 가능성이 있다.
  - **[해결 방안]**
    - `src/renderer/directx9/`, `src/renderer/directx11/`, `src/renderer/directx12/`, `src/renderer/opengl/` 하위 폴더를 만들어 각 백엔드의 `.h`/`.cpp`를 이동한다.
    - 폴더명은 `RendererBackendParser`가 쓰는 Config 문자열 토큰(`"directx9"`/`"directx11"`/`"directx12"`/`"opengl"`)과 동일하게 맞춘다.
    - `src/renderer/`에는 공용 선택 인프라(`IRenderer.h`, `RendererBackend.h`, `RendererBackendParser.h/.cpp`, `RendererFactory.h/.cpp`)만 남긴다.
    - `RendererFactory.cpp`, 관련 테스트 4개, `CMakeLists.txt`의 include/소스 경로를 갱신한다.
  - **[처리 결과]** `directx9/`, `directx11/`, `directx12/`, `opengl/` 4개 하위 폴더로 이동 완료. `RendererFactory.cpp`, 테스트 4개, `CMakeLists.txt` include/소스 경로 갱신. `<d3d9.h>`/`<d3d11.h>`/`<d3d12.h>` 동시 include 파일 없음을 grep으로 재확인.

### 그 외 검사 결과 — 위반 없음

- **SOLID**
  - SRP/OCP/ISP/DIP 위반 없음.
  - `DirectX9Renderer`/`DirectX11Renderer`/`DirectX12Renderer`/`OpenGLRenderer`가 전부 `IRenderer` 하나에만 의존하고, `RendererFactory`/`main()`은 구체 타입을 모른다.
  - `Win32Window`가 `IRenderer`를 전혀 몰라 콜백(`SetResizeCallback`)으로 분리된 구조 유지.
- **라이브러리 격리**
  - `<d3d9.h>`/`<d3d11.h>`/`<d3d12.h>`를 동시에 include하는 파일이 없음을 grep으로 확인 — 각각 `DirectX9Renderer.h`/`DirectX11Renderer.h`/`DirectX12Renderer.h` 한 곳에만 존재.
- **주석 규칙**
  - 신규/수정된 공개 헤더(`IRenderer.h`, `Win32Window.h`, `DirectX9/11/12Renderer.h`, `AppConfig.h` 등) 모두 Author/Description/Input/Output/Notes/Date 빠짐없음.
- **단위 테스트**
  - 모든 항목 해결 후 커버리지 공백 없음.
  - 전체 49개 테스트 통과 (`ctest`).
