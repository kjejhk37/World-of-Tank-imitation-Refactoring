# Strategy — 모델 Importer (Mesh 읽기/저장)

## 개요

Brainstorming에서 확정한 아키텍처를 `src/model_import/` 신규 폴더에 구현한다.
기존 `src/geometry/`, `src/entity_component/`, `src/persistence/` 등과 동일하게 `app_lib` 정적 라이브러리에 편입하고, `CMakeLists.txt`의 `googletest`/`nlohmann_json`/`imgui` 사례와 동일한 패턴으로 세 라이브러리를 `FetchContent`로 통합한다.

**구현 중 발견한 변경 사항**: 공통 지오메트리 구조체 이름을 브레인스토밍 단계에서는 `Mesh`로 논의했으나, 구현 과정에서 `src/geometry/Mesh.h`(충돌 감지용, 이미 존재하는 전역 `struct Mesh`)와 이름이 충돌(ODR 위반)하는 것을 발견해 `ModelMesh`로 변경했다. 자세한 경위는 `docs/commit/모델임포터_Mesh저장_20260723_2240.md` 참고.

## 구현 체크리스트

### 1. CMake — 라이브러리 통합

- [x] `tinyobjloader`를 `FetchContent_Declare`로 선언한다 (v1.0.7 고정). 소비자 CMakeLists를 제공하므로 `nlohmann_json`과 동일하게 `FetchContent_MakeAvailable` + `target_link_libraries(app_lib PRIVATE tinyobjloader)`로 연결했다. (v1.0.7의 CMakeLists가 `cmake_minimum_required(VERSION 2.8.11)`이라 최신 CMake에서 거부되어, `CMAKE_POLICY_VERSION_MINIMUM 3.5`를 이 서브프로젝트 한정으로 임시 설정)
- [x] `ufbx`를 `FetchContent_Declare`로 선언한다 (v0.23.0 고정). 소비자 CMakeLists가 없는 단일 소스 라이브러리이므로 `imgui`와 동일한 패턴 — 소스만 받아오고 `${ufbx_SOURCE_DIR}/ufbx.c`를 `app_lib` 소스 목록에 직접 추가했다. (`ufbx.c`가 C 소스라 루트 `project()`에 `C` 언어를 추가해야 했음)
- [x] `cgltf`를 `FetchContent_Declare`로 선언한다 (v1.15 고정). 단일 헤더 라이브러리라 `CgltfWrapper.cpp` 안에서 `CGLTF_IMPLEMENTATION` 매크로 정의 후 include하고 `target_include_directories(app_lib PRIVATE ${cgltf_SOURCE_DIR})`만 추가했다.
- [x] 세 라이브러리 모두 `PRIVATE` 링크/include로 한정 — grep으로 `main`/`tests` 타겟 소스에서 직접 include 없음을 확인.
- [x] `docs/dependency/tinyobjloader_20260723.md`, `docs/dependency/ufbx_20260723.md`, `docs/dependency/cgltf_20260723.md` 3종 작성 완료.

### 2. 공통 데이터 구조

- [x] `ModelMesh.h` — `positions: vector<Vec3>`, `indices: vector<uint32_t>`, `normals: vector<Vec3>`, `uvChannels: vector<vector<Vec2>>`(이번 사이클은 채널 0만 채움), `materialRef: optional<string>`. 탄젠트/본 필드 없음. (`Vec2`는 기존에 없어 `src/math/Vec2.h`로 신규 추가)
- [x] `Node.h` — `localTransform: Transform`(기존 `src/math/Transform.h` 재사용, Matrix4x4 대신 위치/회전/스케일이 더 다루기 쉬워 선택), `meshIndex: optional<size_t>`, `children: vector<Node>`.
- [x] `Model.h` — `meshes: vector<shared_ptr<const ModelMesh>>`, `rootNode: Node`.

### 3. 포맷별 Importer

- [x] `TinyObjWrapper` — `tiny_obj_loader.h`만 include하는 유일한 지점. `Load(path) -> ModelMesh`.
- [x] `ModelLoader::LoadOBJ(path) -> Model` — 결과 `ModelMesh`를 노드 1개짜리 `Model`로 래핑.
- [x] `UfbxWrapper` — `ufbx.h`만 include하는 유일한 지점. `ufbx_node`/`ufbx_mesh` 구조를 그대로 순회해 씬 그래프 인스턴싱 보존.
- [x] `ModelLoader::LoadFBX(path) -> Model`.
- [x] `CgltfWrapper` — `cgltf.h`만 include하는 유일한 지점. `cgltf_data`의 노드-메쉬 참조 그대로 순회. glTF는 루트 노드가 여럿일 수 있어 identity Transform의 합성 루트로 감쌈. `has_matrix`는 shear 없다는 가정하에 간이 분해.
- [x] `ModelLoader::LoadGLB`/`LoadGLTF -> Model` — 둘 다 `CgltfWrapper::Load` 호출(포맷은 라이브러리가 내용으로 자동 판별).
- [x] 세 Wrapper 모두 라이브러리 객체를 지역 변수로만 생성 — 스레드 안전성 확보.

### 4. 캐시 정책 (전략 패턴)

- [x] `IMeshCachePolicy.h` — `TryGet`/`Store`/`Unload` 순수 가상.
- [x] `RefCountingCachePolicy` — `unordered_map<string, weak_ptr<const Model>>` + `mutex`.
- [x] `LruCachePolicy` — weak_ptr registry + 최근 N개를 강하게 붙잡는 `std::list` 기반 recency 목록 + `mutex`.
- [x] `IFileChangeDetector.h` — `HasChanged(path) -> bool` 순수 가상.
- [x] `Win32FileWatcher` — `ReadDirectoryChangesW`를 전용 워커 스레드에서 실행. 생성자가 첫 `ReadDirectoryChangesW` 호출이 실제로 걸릴 때까지 대기(`m_readyEvent`)한 뒤 반환하도록 구현 — 초기 구현에서는 이 동기화가 없어 "생성자 직후 파일 수정" 테스트가 경쟁 조건으로 실패했음(상세: 커밋 리포트).
- [x] `HotReloadCachePolicy` — `IFileChangeDetector` 주입, 변경 감지 시 캐시 무효화 후 `nullptr` 반환(재로드는 `MeshManager`가 유도).
- [x] 네 클래스 모두 `Unload(key)` 정책 무관 항상 동작 확인(unit test로 검증).

### 5. 중복 제거 (Deduplicator)

- [x] `IMeshDeduplicator.h` — `FindOrRegister(candidate) -> shared_ptr<const ModelMesh>` (find+register를 원자적으로 묶음, Brainstorming 초안의 `FindCongruent` 분리형에서 동시성 안전을 위해 단순화).
- [x] `NaiveSignatureDeduplicator` — 무게중심 기준 정점-거리 정렬 리스트(최댓값 정규화) + 정규화된 표면적 + 정점 개수로 시그니처 구성, registry는 벡터 순차 비교.
- [x] 근사치 한계(비균일 스케일·미러링 미탐지)를 클래스 주석에 명시.

### 6. MeshManager

- [x] `MeshManager` 생성자 — `unique_ptr<IMeshCachePolicy>`(필수) + `unique_ptr<IMeshDeduplicator>`(선택, 기본 `nullptr`) 주입.
- [x] `MeshManager::GetOrLoad(key, loader) -> shared_ptr<const Model>` — 캐시 키는 문자열로 일반화.
- [x] `MeshManager::Unload(key)` — 정책에 위임.
- [x] 스레드 안전성 — `MeshManager` 자체는 락을 걸지 않고 각 정책/Deduplicator 내부 mutex에 위임(서로 다른 키의 동시 로딩을 막지 않기 위해 의도적으로 무락 설계). 같은 키를 여러 스레드가 동시에 첫 로드하면 파싱이 중복 실행될 수 있으나 데이터 손상은 없음 — 클래스 주석에 명시.

### 7. 단위 테스트

- [x] `ModelLoaderTest` — OBJ(직접 작성 큐브)/FBX(ufbx 자체 테스트 데이터 샘플)/GLTF(직접 작성, 임베디드 base64 버퍼)/GLB(같은 GLTF 파일로 `LoadGLB` 공유 검증) + 씬 그래프 인스턴싱(같은 mesh를 노드 2개가 참조) 검증.
- [x] `RefCountingCachePolicyTest` — 자동 해제 + `Unload` 강제 해제.
- [x] `LruCachePolicyTest` — 용량 초과 축출 + recency 갱신 확인.
- [x] `Win32FileWatcherTest` — 실제 임시 디렉터리/파일로 감지 확인 (폴링 대기 상한 2초).
- [x] `HotReloadCachePolicyTest` — stub `IFileChangeDetector` 주입.
- [x] `NaiveSignatureDeduplicatorTest` — 회전/이동/균등스케일 합동 판정 + 비합동 판정.
- [x] `MeshManagerTest` — 정책/Deduplicator 유무별 통합 동작.
- [x] `tests/fixtures/model_import/` — `cube.obj`(직접 작성), `cube.fbx`(ufbx 테스트 데이터, MIT), `triangle.gltf`/`instancing.gltf`(직접 작성).
