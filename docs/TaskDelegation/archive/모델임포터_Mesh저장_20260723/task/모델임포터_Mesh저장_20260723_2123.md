# Task — 모델 Importer (Mesh 읽기/저장)

## Purpose

OBJ/FBX/GLTF/GLB 모델 파일을 읽어 게임에서 공용으로 사용할 Mesh 데이터 구조로 변환·저장하는 Importer 기능을 구현한다.
이 기능은 이후 게임의 모델 로딩 기능으로 편입될 예정이다.
전체 로드맵은 Importer → DX9/11/12 세팅 → Shader 순으로, 이번 Task는 그중 Importer 단계만 다룬다.

## User Draft

대화를 통해 다음 사항이 사전 합의됨.

- 전체 작업은 **Importer / DX 세팅 / Shader** 3개의 독립된 Task Cycle로 나누어 진행한다. 이번 Task는 Importer만 다룬다.
- Importer는 **Entity-Component(ECS)와 완전히 독립**되어야 한다. `IEntity`/`IComponent`/`EntityManager`를 알지 못해야 하며, ECS 쪽에서 Mesh를 참조하는 작업은 이후 별도 사이클로 진행한다.
- 공개 API는 `namespace ModelLoader { Model LoadOBJ(path); Model LoadFBX(path); Model LoadGLB(path); }` 형태의 **상태 없는 네임스페이스 정적 함수**로 둔다. `Model`은 `{ meshes: Mesh[], rootNode: Node }` 구조로, 고유 지오메트리(`meshes[]`)와 이를 참조하는 노드/Transform 계층(`nodes[]`)을 분리해 씬 그래프 내부 인스턴싱(예: 탱크 바퀴 6개가 같은 메쉬를 참조)을 파싱 단계에서 보존한다. OBJ는 씬 그래프가 없어 노드 1개짜리 `Model`로 감싸 반환 타입을 통일한다.
- 단, 외부 라이브러리에 대한 직접 호출은 각 정적 함수가 아니라 **내부 wrapper 클래스**(`TinyObjWrapper`/`UfbxWrapper`/`CgltfWrapper`)가 전담한다. 정적 함수는 이 wrapper 클래스를 함수 내부에서 지역적으로 생성해 호출하는 얇은 퍼사드다. (`agent_harness/CLAUDE.md`의 "외부 라이브러리는 반드시 내부 wrapper 클래스로 감싼다" 원칙 준수)
- Mesh를 **저장(캐싱)할지 여부는 사용자가 `MeshManager`를 통해 선택**한다 (opt-in). Importer 자체(`ModelLoader`)는 캐싱 책임을 갖지 않는다.
- 라이브러리는 Assimp 통합안 대신, 포맷별 경량 라이브러리로 결정됨.
  - OBJ → `tinyobjloader` (MIT 계열)
  - FBX → `ufbx` (MIT/Public Domain)
  - GLTF/GLB → `cgltf` (MIT) — `tinygltf`는 v2가 유지보수 전용 모드로 전환되며 단종 예정이라 배제
- 세 라이브러리 모두 전역/정적 mutable state가 없는 reentrant 설계로 확인됨. wrapper 클래스가 라이브러리 객체를 매 호출마다 지역 변수로 생성하면 멀티스레드 환경에서 파일별 동시 로딩이 안전하다. 단, `MeshManager`의 캐시 동기화는 라이브러리가 보장해주지 않으므로 별도로 설계해야 한다.

## Requirements

- OBJ/FBX/GLTF/GLB 4개 포맷을 읽어 공통 `Model{ meshes: Mesh[], rootNode: Node }` 구조로 변환한다. `Mesh`는 최소 정점/인덱스/노멀/UV를 포함하고, 머티리얼은 실제 텍스처 로딩 없이 참조(인덱스/이름)만 보관한다.
- 탄젠트/바이탄젠트는 Mesh에 저장하지 않고, 노멀맵이 필요해지는 시점에 런타임에 계산한다(Unity `Mesh.RecalculateTangents`와 동일한 접근 — `float4`로 계산해 w에 손잡이(handedness) 부호를 담아 바이탄젠트를 셰이더에서 재구성).
- UV는 최대 8채널까지 확장 가능한 구조(Unity/Unreal과 동일)로 설계하되, 이번 사이클은 최소 채널(1개)만 사용하고 필요할 때마다 채널을 추가한다.
- 본 가중치·인덱스(스키닝)는 Mesh 필드에 포함하지 않는다 — 차체/포탑/포신 등 강체 부품은 Node+Transform으로 충분하고, 캐터필러는 UV 스크롤로 구현하므로 이번 사이클엔 불필요하다. 향후 필요해지면 정점당 최대 4개(Unity의 가변 256개 방식 대신 고정 4개 채택)로 추가한다. 상세 배경은 `docs/algorithm/10_Bone_가중치_스키닝.md` 참고.
- glTF/FBX처럼 씬 그래프가 있는 포맷은 파일이 이미 알려주는 노드-메쉬 참조(내부 인스턴싱, 예: 탱크 바퀴 6개가 같은 메쉬를 참조)를 `nodes[]` 계층 구조로 보존하고 `meshes[]`는 고유 지오메트리만 담아 flatten하지 않는다. OBJ는 씬 그래프가 없어 노드 1개짜리 `Model`로 감싸 반환 타입을 통일한다.
- Importer(`ModelLoader` 네임스페이스)는 `IEntity`/`IComponent`/`EntityManager`를 참조하지 않는다.
- 외부 라이브러리(`tinyobjloader`/`ufbx`/`cgltf`) 직접 호출은 각각의 내부 wrapper 클래스 안에만 존재해야 하고, 다른 모듈이 라이브러리를 직접 include하지 않는다.
- `Model.meshes`는 `Mesh` 값 복사가 아니라 `shared_ptr<const Mesh>` 핸들의 목록이다. `Node`는 이 목록의 인덱스(또는 핸들)를 참조한다. 같은 파일 내부의 씬 그래프 인스턴싱(예: 바퀴 6개)은 `MeshManager` 없이 파싱 단계에서 이미 해결된다.
- `MeshManager`는 캐시 키(현재는 파일 경로, 향후 절차적 프리미티브 등도 고려해 **의미상 고유 식별자 문자열**로 취급)별로 `Model`을 opt-in 캐싱하며, 캐시 접근에 대한 스레드 안전성을 확보한다.
- `MeshManager`는 `Model`(및 그 안의 `Mesh`들)을 값 복사가 아니라 참조/핸들(예: `shared_ptr<const Model>`/`shared_ptr<const Mesh>`)로 반환하여, 동일 지오메트리를 여러 Transform으로 배치(인스턴싱)할 때 메모리 중복을 피한다.
- 서로 다른 파일 간 임의-Transform 기하 합동(congruence) 탐지를 위한 중앙 Mesh 풀은 `MeshManager` 내부에만 존재한다 (`Model`이나 `ModelLoader`가 아님). `ModelLoader`를 `MeshManager` 없이 직접 호출하면 파일 간 중복 제거는 적용되지 않는다(같은 파일 내부 인스턴싱만 적용됨) — 상태 없는 정적 함수 원칙과 일관됨.
- 위 중앙 풀에 대한 탐지는 `IMeshDeduplicator` 인터페이스로 이번 사이클에 포함한다. 개별 `Mesh`(지오메트리) 단위로, 여러 `Model`에 걸쳐 비교한다. 기본 구현(`NaiveSignatureDeduplicator`)은 회전·이동·균등 스케일에 불변한 저비용 근사 시그니처 비교이며, 정확한 형상 정합이 아닌 휴리스틱임을 문서화한다. (향후 별도 "mesh 전처리" 프로젝트/submodule이 더 정교한 구현으로 교체 가능하도록 인터페이스 경계를 지금 확정해두는 목적. 같은 파일 내부 인스턴싱으로 이미 대부분의 실사용 이점을 얻으므로, 이 중앙 풀이 추가로 주는 이점 자체는 크지 않다는 점을 인지하고 진행함)
- 절차적 프리미티브(Sphere/Cube/Cylinder 등) 생성기 구현은 "파일을 읽는" Importer 책임과 무관하므로 이번 사이클 스코프에서 제외한다. 단, 캐시 키를 파일 경로로 좁게 고정하지 않고 고유 식별자 문자열로 취급해두어, 향후 생성기가 같은 `MeshManager`를 재사용할 수 있도록 열어둔다.
- `MeshManager`의 캐시 정책은 **전략 패턴**(`IMeshCachePolicy` 인터페이스)으로 구현하며, 생성 시점에 정책 하나를 주입받아 사용한다 (런타임 정책 교체는 스코프 제외).
  - `Unload(path)`는 인터페이스에 포함되어 어떤 정책을 쓰든 항상 제공되는 명시적 해제 수단이다.
  - `RefCountingCachePolicy` — `weak_ptr` 기반, 마지막 참조 소멸 시 자동 해제.
  - `HotReloadCachePolicy` — 원본 파일 변경 감지 시 캐시를 무효화하고 재로드.
  - `LruCachePolicy` — 최근 사용된 N개(또는 메모리 예산 이내)를 `shared_ptr`로 강하게 유지, 초과분부터 축출.
- `HotReloadCachePolicy`의 파일 변경 감지는 `IFileChangeDetector` 인터페이스로 추상화한다.
  - 이번 사이클: `Win32FileWatcher` (Win32 `ReadDirectoryChangesW`를 감싼 wrapper 클래스, 전용 워커 스레드에서 동작, 게임의 메인 윈도우 메시지 루프와는 독립) 구현.
  - 백로그: `PollingHashFileWatcher` (수정 시각/해시 비교 방식) — 인터페이스만 열어두고 이번 사이클에서는 구현하지 않음.
- 각 wrapper 클래스와 `MeshManager`(각 캐시 정책, `Win32FileWatcher`, `IMeshDeduplicator` 포함)에 대해 unit test를 작성한다.
- CMake 빌드에 세 라이브러리(`tinyobjloader`/`ufbx`/`cgltf`)를 `FetchContent`로 통합한다 (`googletest`/`nlohmann_json` 도입 때와 동일한 패턴).
