### 지금 있는 것 (2026-08-11 사이클에서 이식됨)

- `GameManager` — 조립 지점(composition root). `SceneManager` 소유, `PrototypeScene` 하나만 생성자에서 등록·활성화. Device/Audio/Font/ImGui 초기화나 자체 렌더 루프는 없음(원본과 이름만 동일).
- `SceneManager` — 씬을 key로 등록(`Create`)/활성화(`Add`)/비활성화(`Remove`), 활성 씬들의 `Update` 위임. 원본과 달리 싱글턴 아님.
- `Scene`(추상) — `Start`/`Update(dt)`/`End` 생명주기 + 자신이 만든 Entity 목록 보유. `PreRender`/`Render`/`PostRender`/`GUIRender`는 없음.
- `PrototypeScene` — 원본 `TestScene`을 대체하지만, 탱크 모델·충돌체·이펙트 없이 기존 `InstanceUpdateWorker`의 격자 배치 + bob + 회전 데모 수식만 Scene/Entity 경유로 재현.
- `TransformComponent` — Entity 하나당 위치/회전/스케일만 담는 최소 Component.
- `SceneSnapshotBuilder` — 활성 씬들의 `TransformComponent`를 모아 `graphics/renderer::InstanceSnapshot`으로 변환.
- 엔진/렌더 스레드 분리 유지 — `SceneManager`+`Scene::Update()`는 `InstanceUpdateWorker`(engine 스레드) 안에서 돌고, `SceneSnapshotBuilder`가 만든 스냅샷을 `DoubleBufferPublisher`로 렌더 스레드에 넘긴다.

- `Scene/WOT/WOT.cpp/h` — 원본에서도 빈 스텁, 실제 게임 진입 씬으로 채워야 할 자리.
- `Scene/` 아래 데모/튜토리얼 씬 12개 — 2026-08-11 사이클 브레인스토밍에서 이식 대상 제외로 확정(포트폴리오 목표와 무관).

### 보류(DEFERRED)된 설계 이슈 — 2026-08-11 사이클 Refactor Inspection

- **Entity 제거(수명주기) 미설계** — `Scene`은 `CreateEntity()`만 있고 제거 경로가 없음. Entity를 실제로 지워야 하는 기능(예: 전차 파괴)이 생기면 `Scene::m_entities`(열거용)와 `EntityManager`(소유) 두 자료구조를 동시에 갱신하는 API 설계 필요.
- **`GameManager`의 씬 하드코딩** — 현재 씬을 정확히 1개(`"Prototype"`)만 등록. 로딩 화면 → 실제 게임플레이 전환처럼 씬이 여러 개 필요해지면 `GameManager`가 씬 목록/설정을 받는 형태로 바뀌어야 함.
- **얇은 데이터/기반 타입의 테스트 관례 미확정** — `TransformComponent`/`Scene`처럼 얇은 타입에 전용 테스트를 둘지, 지금처럼 소비자 테스트로만 간접 검증할지 프로젝트 차원 결정 없음.
