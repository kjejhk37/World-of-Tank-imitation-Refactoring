# Code Review (Stage 1): 게임 기본 기능 채우기 (IntroScene 4/5종 위젯)

이번 사이클에서 WOT 저장소에 새로 만들거나 수정한 코드(`main.cpp`, `GameManager`, `IntroScene`, `InstanceUpdateWorker`, 관련 테스트 4개, `CMakeLists.txt`)를 SOLID/라이브러리 격리/테스트/주석 규칙 기준으로 검토했다. `graphics` 저장소가 응답으로 넘겨준 코드(`ButtonUI` 등)는 이 사이클에서 WOT이 작성한 코드가 아니므로 검토 대상에서 제외했다.

## 발견 사항

- [LOW] `IntroScene.h`의 클래스 주석이 최종 구현과 어긋났었다.
  - 원래 주석은 "위젯은 graphics 응답을 받은 뒤 채워진다"고 되어 있었는데, 실제로는 엔진/렌더 스레드 경계 문제 때문에 위젯 5종을 `IntroScene`이 아니라 `main.cpp`(렌더 스레드)에 배선하기로 최종 결정했다.
  - `IntroScene`은 "나중에 위젯이 채워질 자리"가 아니라 "의도적으로 계속 비어있는 엔진 스레드 씬"인데, 주석은 여전히 전자로 읽혔다.
  - **[해결 방안]**
    - `IntroScene.h`의 Description/Notes를 갱신해, 위젯이 `main.cpp`(렌더 스레드)에 있는 이유(엔진/렌더 스레드 분리, ImGui 스레드 세이프티 문제)를 명시.
  - **처리 결과**: 주석 갱신 완료, 재빌드·재테스트(279개) 통과 확인.

- [LOW] `main()`이 "Intro 화면 UI 구성"이라는 별개 책임을 앱 부트스트랩 로직과 함께 떠안고 있었다(SRP).
  - config 로드 → 창 생성 → 렌더러 초기화 → Intro 위젯 5종 생성/등록 → engine worker 시작 → 메시지 루프, 총 5단계 책임이 한 함수에 있었다.
  - `platform_graphics_projects.md`가 "main.cpp의 루프 오케스트레이션은 projects 소속, graphics로 추출 금지"라고 명시해 완전히 별도 파일로 빼는 건 이 프로젝트 관례에 안 맞는다.
  - **[해결 방안]**
    - `main.cpp` 안의 로컬 구조체 `IntroUi` + 팩토리 함수 `BuildIntroUi(IRenderer&)`로 추출.
  - **처리 결과**: 추출 완료. 추출 과정에서 **잠재적 버그를 하나 미리 차단**했다 — `IntroUi`는 `registry`가 같은 구조체 안의 위젯들 주소(`&titleLabel` 등)를 참조하는 자기참조 구조라, 값으로 반환(`return ui;`)했다면 NRVO(Named Return Value Optimization)가 적용되지 않는 컴파일러/빌드 설정에서 이동 생성 시 주소가 바뀌어 `registry`가 댕글링 포인터를 가리키게 될 위험이 있었다. 이를 `std::unique_ptr<IntroUi>`로 힙에 배치해(`std::make_unique`) 포인터만 이동시키는 방식으로 바꿔, NRVO 여부와 무관하게 항상 안전하도록 설계했다.
  - 재빌드·재테스트(279개) 통과, `main.exe --backend=dx11` 재실행(8초 무크래시) 확인.

발견된 이슈 2건 모두 해결 완료.
