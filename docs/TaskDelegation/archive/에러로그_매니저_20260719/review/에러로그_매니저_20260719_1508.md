# Code Review: 에러/로그 매니저

## Stage 1 — Quality Inspection

### 즉시 해결 가능 (이번 Task 범위 내)

- `[LOW]` `FileLogSinkTest::EmptyPathNeverCreatesFile`가 실제로 "파일이 생성되지 않음"을 검증하지 않는다.
  - 경로가 빈 문자열이라 확인할 파일 경로 자체가 없어서, 현재는 `Write()` 호출이 크래시하지 않는다는 것만 확인한다.
  - 테스트 이름이 약속하는 내용(파일 미생성)과 실제 검증 내용이 어긋난다.
  - **[해결 방안]**
    - `FileLogSink`에 `bool IsEnabled() const`(내부적으로 `m_file.is_open()` 반환) 접근자를 추가한다.
    - `EmptyPathNeverCreatesFile`에서 `EXPECT_FALSE(sink.IsEnabled())`로, 정상 경로 테스트에서는 `EXPECT_TRUE(sink.IsEnabled())`로 실제 상태를 검증하도록 보강한다.
  - **[처리 결과]** `FileLogSink`에 `bool IsEnabled() const` 접근자 추가. `EmptyPathNeverCreatesFile`은 `EXPECT_FALSE(sink.IsEnabled())`로, `WriteAppendsAndFlushesImmediately`는 `EXPECT_TRUE(sink.IsEnabled())`로 실제 상태를 검증하도록 보강.

- `[LOW]` `Logger.h`의 Notes가 "여러 스레드에서 동시에 호출해도 안전하다"고 명시하지만, 이를 실제로 검증하는 단위 테스트가 없다.
  - `std::mutex`로 보호하고 있다는 사실은 코드로 확인되지만, 동시 호출 시 로그 유실/손상이 없는지는 테스트되지 않았다.
  - **[해결 방안]**
    - `LoggerTest`에 여러 스레드에서 동시에 `Info()`를 호출한 뒤, `FakeLogSink`가 받은 호출 총 개수가 (스레드 수 × 호출 수)와 정확히 일치하는지 검증하는 케이스를 추가한다.
  - **[처리 결과]** `LoggerTest::ConcurrentCallsFromMultipleThreadsDoNotLoseOrCorruptEntries` 추가 — 8개 스레드 × 50회 호출 후 `FakeLogSink`가 받은 총 개수가 정확히 400건임을 검증(mutex 보호 없이는 `std::vector`에 대한 동시 `emplace_back`으로 크래시하거나 유실될 수 있음).

### 그 외 검사 결과 — 위반 없음

- **SOLID**
  - `LogFormatter`(포맷)/`ILogSink`(출력 추상화)/`ConsoleLogSink`·`FileLogSink`(구체 출력)/`Logger`(분배)/`Log`(전역 접근)로 책임이 명확히 분리되어 있다.
  - `Logger`는 `ILogSink` 인터페이스에만 의존한다(DIP).
  - `ErrorCode`는 `LogFormatter`/`ILogSink`에 노출되지 않는다(SRP 경계 유지 — 코드 번호를 메시지에 삽입하는 책임은 `Logger::Error`에만 있음).
- **라이브러리 격리**
  - 새로 추가된 외부(서드파티) 라이브러리 없음.
  - `windows.h`(`GetStdHandle`)는 `IRenderer.h` 선례와 동일하게 플랫폼 API라 wrapper 규칙 대상이 아니며, `ConsoleLogSink.cpp` 한 파일에만 격리되어 있다.
- **주석 규칙**
  - 신규 헤더(`ErrorCode.h`, `ILogSink.h`, `ConsoleLogSink.h`, `FileLogSink.h`, `Logger.h`, `Log.h`, `LogFormatter.h`) 전부 Author/Description/Input/Output/Notes/Date 빠짐없이 포함.
- **단위 테스트**
  - 위 2건을 제외하면 커버리지 공백 없음.
  - `fprintf`/`cstdio` 잔재 없음(main.cpp grep으로 재확인).

### 처리 상태

2개 항목 모두 `[RESOLVED]` — 재빌드/재테스트(64개 전부 통과) 완료.
