# Strategy: 에러/로그 매니저

## 적용 방식 요약

브레인스토밍에서 확정된 설계를 `src/logging/` 신규 디렉토리에 구현한다 — 레벨/코드 정의 → 포맷터 → 싱크(콘솔/파일) → `Logger`(포맷+분배) → 전역 래퍼(`Log`) → `AppConfig` 필드 → `main.cpp` 배선.

- `LogLevel{Info,Warning,Error}` + `타입 : 시간 : 내용` 포맷, `ErrorCode`는 카테고리별 번호 대역(1000=Launch/Config, 2000=플랫폼/윈도우, 3000=렌더러)으로 4개 값을 정의한다.
- 콘솔 출력은 표준 출력/에러 핸들이 유효할 때만 수행하고(구현 중 `GetConsoleWindow()`에서 `GetStdHandle()` 검사로 변경 — 아래 3번 항목 참고), `Error`/`Warning`은 `stderr`, `Info`는 `stdout`으로 분리한다.
- 파일 출력은 `AppConfig.logFilePath`(`config.json`)가 비어있으면 `FileLogSink`가 완전히 no-op(널 오브젝트)으로 동작한다.
- 파일은 `Init` 시점에 append 모드로 한 번 열고, 모든 레벨의 로그를 매 호출 직후 `flush()`한다(실시간 저장).
- `Logger`는 인스턴스 가능한 클래스(SRP: 포맷+분배만 담당)로 만들고, `std::mutex`로 출력 경로를 보호한다.
- 전역 접근은 `LaunchConfigStore`와 동일한 패턴(익명 네임스페이스 전역 + `Log::Init/Info/Warning/Error` 네임스페이스 함수)으로 얇게 감싼다.
- `main.cpp`의 기존 4개 `std::fprintf(stderr, ...)` 호출부를 `Log::Error(ErrorCode::..., message)`로 교체한다.

## 구현 체크리스트

### 1. 레벨/코드 정의

- [x] `src/logging/LogLevel.h` — `enum class LogLevel { Info, Warning, Error }`
- [x] `src/logging/ErrorCode.h` — `enum class ErrorCode`, 카테고리별 번호 대역으로 4개 값 정의(`LaunchConfigParseFailed=1001`, `WindowCreationFailed=2001`, `UnknownRendererBackend=3001`, `RendererInitializationFailed=3002`)

### 2. 포맷터

- [x] `src/logging/LogFormatter.h/.cpp` — `FormatLogLine(LogLevel, const std::string& message, std::time_t timestamp = std::time(nullptr))`, `localtime_s` + `std::put_time`으로 `"타입 : YYYY-MM-DD HH:MM:SS : 내용"` 조립
- [x] 단위 테스트: 고정된 `std::time_t` 값을 주입해 각 레벨(`Info`/`Warning`/`Error`)에 대해 출력 문자열이 정확히 일치하는지 검증

### 3. 싱크 (`ILogSink` + 구현체)

- [x] `src/logging/ILogSink.h` — `virtual void Write(LogLevel level, const std::string& formattedLine) = 0`
- [x] `src/logging/ConsoleLogSink.h/.cpp` — `Error`/`Warning`은 `std::cerr`, `Info`는 `std::cout`
  - **구현 중 변경**: 최초안은 `GetConsoleWindow() == NULL`로 콘솔 유무를 판단했으나, ctest가 출력을 캡처하는 환경처럼 콘솔 창이 없어도 표준 출력이 파일/파이프로 정상 리다이렉트되는 경우까지 막아버리는 문제가 있어(실제 테스트에서 3건 실패로 발견), `GetStdHandle(STD_OUTPUT_HANDLE/STD_ERROR_HANDLE)`의 핸들 유효성 검사로 대체함. 콘솔 직접 연결/리다이렉트 모두 정상 기록되고, 핸들 자체가 없는 경우(WIN32 서브시스템 등)만 조용히 생략된다.
- [x] 단위 테스트: GoogleTest `CaptureStdout`/`CaptureStderr`로 레벨별 출력 스트림이 올바른지 검증
- [x] `src/logging/FileLogSink.h/.cpp` — 생성자에서 경로가 비어있으면 파일을 열지 않고(널 오브젝트) `Write`가 즉시 반환, 경로가 있으면 append 모드로 열어 유지하고 `Write` 호출마다 한 줄 쓰고 `flush()`
- [x] 단위 테스트: `std::filesystem::temp_directory_path()`에 임시 파일 경로를 만들어 (1) 경로 지정 시 각 `Write` 호출 직후 파일 내용이 즉시 반영되는지, (2) 빈 경로일 때 파일이 전혀 생성되지 않는지 검증 (테스트 종료 시 임시 파일 정리)

### 4. `Logger` (핵심 로직)

- [x] `src/logging/Logger.h/.cpp` — 생성자 `explicit Logger(std::vector<std::unique_ptr<ILogSink>> sinks)`, `Info(message)`/`Warning(message)`/`Error(ErrorCode, message)` 공개 메서드, 내부 `Log(level, message)`가 포맷 후 `std::mutex`로 보호된 구간에서 모든 싱크에 분배
- [x] `Error`는 메시지 앞에 `"[코드번호] "`를 붙여 `Log(LogLevel::Error, ...)`에 전달 (포맷터는 `ErrorCode`를 모르게 유지 — SRP)
- [x] 단위 테스트: 테스트 전용 Fake `ILogSink`(호출 인자를 벡터에 기록)를 주입해, `Info`/`Warning`/`Error` 각각 호출 시 올바른 레벨과 포맷된 문자열로 모든 등록된 싱크에 전달되는지 검증

## 최종 승인 및 검증 기준

- CMake로 `main`, `tests` 타겟이 모두 정상 컴파일·링크된다.
- `tests` 타겟의 모든 케이스(포맷터, 콘솔/파일 싱크, `Logger`, 전역 `Log`, `ConfigManager` 신규 케이스 포함)가 통과한다.
- `config.json`에 `logFilePath`를 지정하지 않으면 `.txt` 파일이 전혀 생성되지 않는다(수동 확인).
- `config.json`에 `logFilePath`를 지정하면 `main.exe` 실행 중 발생한 에러 로그가 즉시(실시간) 해당 `.txt` 파일에 반영된다(수동 확인).
- `main.cpp`의 기존 4개 에러 지점이 각각 대응하는 `ErrorCode`로 로깅된다.
- `Logger`/`ConsoleLogSink`/`FileLogSink`/`LogFormatter`가 각각 단일 책임만 가지는지 코드 리뷰로 확인한다 (SRP).
- 신규 작성된 모든 함수/클래스에 CLAUDE.md 주석 규칙(Author / 설명 / Input / Output / Notes / Date)이 반영되어 있다.
