# Strategy: 커스텀 FCL 통합 파이프라인 (로드맵 10번, 마지막)

## 적용 방식

브레인스토밍에서 확정한 대로, 실제 외부 FCL 라이브러리를 쓰지 않고 이번 사이클에서 만든 broad-phase(BVH) + narrow-phase(GJK+EPA) 모듈을 엮은 통합 파이프라인을 직접 구현한다. **요구사항 1(모든 알고리즘은 서로 독립)의 명시적 예외**로, 이 모듈만 다른 두 모듈(`Bvh`, `GjkEpa`)을 include한다 — 다른 모듈들이 먼저 완성되어 있어야 하므로 로드맵상 항상 마지막에 온다.

### 파일 구성 (`src/collision/fcl/`)

- `Fcl.h`/`.cpp` — `struct CollisionPair { size_t indexA; size_t indexB; PenetrationInfo penetration; }; class Fcl { explicit Fcl(const std::vector<Geometry>&); std::vector<CollisionPair> DetectCollisions() const; };`

### 알고리즘 개요

1. **Broad-phase**: 생성자에 전달된 Geometry 목록으로 `Bvh`를 빌드하고 `FindOverlappingPairs()`로 AABB가 겹치는 후보 쌍을 추린다.
2. **Narrow-phase**: 각 후보 쌍에 대해 `ComputePenetration()`(GJK+EPA)을 호출 — AABB는 겹쳤지만 실제 도형은 안 닿는 경우(broad-phase의 전형적인 오탐)를 걸러내고, 실제로 충돌하는 쌍만 침투 법선+깊이와 함께 최종 결과에 남긴다.

이 파이프라인이 바로 "FCL(Flexible Collision Library)"류 라이브러리가 실제로 하는 일 — broad-phase로 싸게 후보를 추리고, narrow-phase로 정확하게 확정한다.

### 테스트 전략

AABB는 겹치지만 실제 구는 서로 닿지 않는 쌍(broad-phase 오탐, narrow-phase가 걸러내야 함) + 실제로 겹치는 쌍(최종 결과에 남아야 하며 깊이 값도 검증) + 완전히 무관한 고립 객체를 함께 배치해 파이프라인 전체가 올바르게 동작하는지 검증한다.
