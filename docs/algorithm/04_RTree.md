# R-Tree — 점진적으로 자라는 경계 상자 트리

**분류**: broad-phase.
**선행 지식**: [03_BVH.md](03_BVH.md) — R-Tree는 BVH와 "같은 문제를 트리로 푼다"는 목표는 같지만 빌드 방식이 근본적으로 다르다.

## BVH와의 차이 (가장 중요한 포인트)

BVH는 "객체 목록을 한꺼번에 받아서 top-down으로 짓는" 정적 구조다.
R-Tree는 "`Insert()`를 한 번에 하나씩 호출해서 점진적으로 자라는" 동적 구조다.
그래서 이 프로젝트의 `RTree` 클래스는 BVH와 달리 생성자 이후에도 `Insert()`로 객체를 계속 추가할 수 있다 — 이게 R-Tree를 굳이 따로 구현한 이유다(게임에서 객체가 계속 생기고 없어지는 상황에 더 자연스러운 모델).

## 알고리즘 (Guttman의 고전 R-Tree, 1984)

**삽입**

1. 리프까지 내려가며, 매 단계에서 "새 항목을 포함하도록 넓혔을 때 부피 증가가 가장 작은" 자식을 고른다(`ChooseSubtree`) — 새 항목이 최대한 "제자리"에 들어가게 하기 위함.
2. 리프에 도착하면 항목을 추가한다.
3. 노드의 항목 수가 상한(`kMaxEntries=4`)을 넘으면 **분할(split)**한다.

**분할 (Quadratic Split)**

1. 넘친 노드의 항목들 중, 함께 묶었을 때 "낭비"(합친 부피 − 각자 부피의 합)가 가장 큰 두 항목을 시드로 고른다 — 이 둘은 서로 가장 안 어울리는 조합이라 각자 다른 그룹의 대표가 된다.
2. 남은 항목들을 하나씩, 부피 증가가 더 적은 쪽 그룹에 배정한다(단, 최소 항목 수를 못 채울 상황이면 강제 배정).
3. 분할로 생긴 새 노드는 **부모 노드에 새 항목으로 추가**되고, 부모도 넘치면 같은 방식으로 분할 — 루트까지 전파되면 트리 높이가 1 늘어난다.

**쿼리(자기 충돌)**: BVH와 원리는 같은 "내부 쌍 + 교차 쌍 + 재귀" 패턴이지만, R-Tree 노드는 자식이 2개가 아니라 최대 4개(N-ary)라서 "서로 다른 자식 쌍 전부"에 대해 교차 검사를 한다.

## 이 프로젝트에서의 구현

- 파일: `src/platform/collision/rtree/RTree.h`/`.cpp`
- `class RTree` — `RTree()`(빈 트리) 또는 `RTree(objects)`(objects를 하나씩 `Insert()`), `void Insert(const Geometry&)`, `FindOverlappingPairs()`.
- `kMaxEntries=4`, `kMinEntries=2` 고정값 사용(동적 튜닝은 범위 밖).
- 테스트에서 10개의 분리된 객체로 분할이 실제로 일어나는지, 분할 후에도 겹침 판정이 정확한지(6개 겹치는 객체 → C(6,2)=15쌍 전부 검출), 생성자 이후 `Insert()`로 추가한 객체의 겹침도 정상 검출되는지 확인했다.

## 언제 쓰는가

- 객체가 계속 추가/삭제되는 동적인 씬(R*-Tree 등 삽입/삭제가 잦은 변형도 존재, 이번 사이클 범위는 기본 삽입만).
- 원래는 공간 데이터베이스(PostGIS 등)에서 지리 정보 색인용으로 널리 쓰이던 자료구조 — "박스들의 집합을 효율적으로 색인"한다는 문제 자체가 게임의 broad-phase와 본질적으로 같다.
- 단점: BVH의 top-down 빌드보다 트리 품질이 들쭉날쭉할 수 있음(삽입 순서에 따라 분할 결과가 달라짐).
