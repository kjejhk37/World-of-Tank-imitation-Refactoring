# Octree / k-d Tree — 참고용 대안 구조

**분류**: broad-phase (참고용, 낮은 우선순위).
**선행 지식**: [03_BVH.md](03_BVH.md), [05_Voxel_SpatialHashing.md](05_Voxel_SpatialHashing.md).

이 둘은 각각 BVH·Voxel과 목적이 겹쳐서(브레인스토밍 단계에서 "참고용, 낮은 우선순위"로 분류됨) 폭넓게 다루지는 않았지만, **핵심 차별점 하나씩만 정확히 구현**해뒀다 — 무엇이 다른지 아는 것 자체가 학습 포인트다.

## Octree — Voxel의 적응형(adaptive) 버전

Voxel Grid는 셀 크기가 어디서나 균일하다.
Octree는 대신 **밀도에 따라 재귀적으로 8분할**한다 — 객체가 많이 몰린 영역만 더 잘게 쪼개고, 텅 빈 영역은 큰 칸 하나로 둔다.

**이 프로젝트의 삽입 정책**: 객체를 "완전히 들어맞는 가장 깊은 자식"에만 배치한다.
어느 자식에도 완전히 들어맞지 않으면(중심선을 걸치면) 그 객체는 현재(더 얕은) 노드에 남긴다 — Voxel Grid처럼 "여러 셀에 걸쳐 등록"하지 않고, 딱 한 곳에만 저장하는 대신 계층을 걸쳐서 저장한다는 뜻이다.

**쿼리**: 각 노드에서 (a) 그 노드 자신에 저장된 객체끼리, (b) 그 노드의 객체 대 모든 자손, (c) 각 자식으로 재귀 — 이 세 경우가 정확히 한 번씩만 겹쳐 누락/중복이 없다.

- 파일: `src/collision/octree/Octree.h`/`.cpp`
- 단순화: 이미 저장된 객체는 나중에 노드가 분할돼도 재분배하지 않는다(정확성에는 영향 없음, 트리 품질에만 영향).

## k-d Tree — BVH의 "축 순환" 버전

트리 형태(이진 트리 + self-collide 쿼리)는 BVH와 완전히 같다.
**유일한 차이**: BVH는 매번 "가장 넓은 축"을 고르지만, k-d Tree는 이름 그대로 **깊이에 따라 축을 순환**(depth % 3 → x, y, z, x, y, z, ...)하며 그 축의 중심점 중앙값으로 분할한다.

이 하나의 차이가 k-d Tree라는 이름의 유래이자 정체성이다("k-dimensional tree" — k개 차원을 돌아가며 분할).

- 파일: `src/collision/kdtree/KdTree.h`/`.cpp`
- BVH 코드를 `#include`하지 않고 완전히 독립적으로 다시 작성(요구사항: 모든 알고리즘은 서로 독립).

## 언제 쓰는가

- **Octree**: 밀도가 불균일한 3D 씬(오픈월드 등)에서 Voxel Grid보다 메모리를 아끼고 싶을 때. 다만 구현 복잡도가 더 높음.
- **k-d Tree**: 원래는 정적 데이터의 최근접점/레이 쿼리에 강점이 있는 구조(레이트레이싱 등). 동적으로 자주 바뀌는 씬에는 BVH/R-Tree가 더 흔히 쓰임.
- 이 프로젝트에서는 둘 다 "BVH/Voxel과 비교하며 차이를 이해하기 위한" 참고용 구현이다.
