# BVH (Bounding Volume Hierarchy) — 경계 상자로 만든 이진 트리

**분류**: broad-phase.
**선행 지식**: [00_Geometry_공용입력타입.md](00_Geometry_공용입력타입.md)의 `GetBounds()` 함수, [02_SweepAndPrune.md](02_SweepAndPrune.md)(같은 문제를 푸는 대안으로 비교하며 읽으면 좋음).

## 왜 필요한가

Sweep and Prune은 "매번 새로 정렬"하는 1회성 계산이다.
반면 실제 게임에서는 같은 씬을 **한 프레임에도 여러 번** 질의하고 싶을 때가 있다(예: 여러 종류의 질의, 여러 시스템에서 같은 공간 정보 재사용).
BVH는 "한 번 트리를 지어두고, 그 트리를 여러 번 재사용"할 수 있는 자료구조라는 점이 SAP과의 본질적 차이다.

## 핵심 아이디어

각 객체를 감싸는 AABB를 리프(leaf)로 삼고, 리프들을 **점점 더 큰 AABB로 묶어 올라가는 이진 트리**를 만든다.
루트 노드의 AABB는 모든 객체를 감싸고, 자식으로 내려갈수록 더 좁은 영역만 감싼다.
쿼리할 때 부모 노드의 AABB가 안 겹치면 그 자식들은 아예 볼 필요가 없다 — 이게 트리 구조의 이득이다.

## 빌드 (Top-down, median split)

1. 모든 객체의 AABB를 구한다.
2. 현재 범위(처음엔 전체)의 결합 AABB를 구하고, 그중 **가장 넓은 축**(x/y/z 중 extent가 가장 큰 것)을 고른다.
3. 그 축을 기준으로 객체들의 중심점(centroid) **중앙값**으로 절반씩 나눈다(`std::nth_element` 사용).
4. 왼쪽/오른쪽 각각에 대해 재귀적으로 1~3을 반복, 원소가 1개가 되면 리프로 만든다.

이 프로젝트는 **중앙값 분할**을 쓴다 — 트리 품질(질의 속도)을 더 최적화하는 SAH(Surface Area Heuristic) 같은 기법도 있지만 이번 사이클 범위 밖으로 뒀다.

## 쿼리: 자기 자신과의 충돌(Self-Collide)

BVH 하나를 가지고 "이 안의 모든 객체 쌍 중 겹치는 것"을 찾으려면, 단순히 루트를 자기 자신과 비교하면 안 된다(중복/누락 발생).
표준적으로 쓰이는 트릭(Bullet 등에서도 사용)은 다음과 같다.

```
SelfCollide(node):
    if node가 리프: return  (리프 안에는 객체가 하나뿐이라 더 볼 게 없음)
    SelfCollide(node.left)              # 왼쪽 서브트리 내부 쌍
    SelfCollide(node.right)             # 오른쪽 서브트리 내부 쌍
    CollectOverlaps(node.left, node.right)  # 왼쪽-오른쪽 사이의 쌍만
```

`CollectOverlaps(a, b)`는 두 노드의 AABB가 안 겹치면 즉시 포기하고, 겹치면 각각의 자식으로 내려가며 재귀한다.
이렇게 세 부분(왼쪽 내부/오른쪽 내부/왼쪽-오른쪽 교차)으로 나누면 모든 쌍을 정확히 한 번씩만 검사하게 된다.

## 이 프로젝트에서의 구현

- 파일: `src/platform/collision/bvh/Bvh.h`/`.cpp`
- `class Bvh` — 생성자에서 트리를 빌드하고, `FindOverlappingPairs()`로 쿼리(SAP과 반환 타입이 동일해 비교하기 쉽게 맞춤).
- 리프-리프 최종 확인은 기존 `Intersects(AABB,AABB)` 재사용.

## 복잡도

- 빌드: O(n log n)(정렬 포함).
- 자기 충돌 쿼리: 이상적으로는 O(n log n)에 가깝지만, 씬 구성에 따라 달라짐.

## 언제 쓰는가

- 씬이 자주 안 바뀌거나, 한 번 짓고 여러 번 질의할 상황.
- 정적/준정적 지형, 큰 메시의 삼각형 가속 구조 등에 실무에서 표준적으로 쓰임(이번 사이클은 객체 단위만 다룸, 메시 내부 삼각형 가속은 범위 밖).
- 단점: 객체가 매 프레임 크게 움직이면 트리를 다시 짓거나 갱신하는 비용이 발생 — 이럴 때 R-Tree의 점진적 삽입이 유리할 수 있음.
