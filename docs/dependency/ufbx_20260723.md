# Step 1 — Evaluation

## Alternatives

| | ufbx | Assimp(FBX 지원) | OpenFBX |
|---|---|---|---|
| 기능 범위 | FBX 전용, FBX SDK 수준 기능 목표 | FBX 포함 40+ 포맷, 풀 씬 그래프 | FBX 전용, 경량이지만 기능 범위 제한적 |
| 실사용 검증 | Blender 4.5가 FBX 임포터로 채택 | 널리 쓰이나 스켈레탈 데이터 다루기 번거롭다는 평 | 상대적으로 마이너 |
| 통합 난이도 | 단일 소스(ufbx.h/.c), CMakeLists 미제공 | 대형 의존성 | 단일 소스 |
| 라이선스 | MIT/Public Domain | BSD-3 계열 | MIT |

포맷별 경량 라이브러리 방향(방향 B)에 따라 FBX 전용 라이브러리 중 가장 실사용 검증이 강한 ufbx를 선택했다.

## Maintenance Status

- 최신 안정 릴리스: v0.23.0.
- 활발히 유지보수 중이며(Blender의 공식 FBX 임포터 채택이라는 강한 실사용 검증), 저장소가 방치된 상태 아님.

## License

- MIT 또는 Public Domain(둘 중 선택 가능). Permissive, 카피레프트 없음. 라이선스 충돌 없음.

## Risks

- 정점 속성이 "값 목록 + 인덱스" 구조(`ufbx_vertex_vec3.values`/`.indices`)라 우리 `Mesh`가 기대하는 "정점당 위치/노멀/UV가 한 세트로 묶인" 형태로 변환하는 과정이 필요하다 — `UfbxWrapper`가 `ufbx_triangulate_face`로 각 면을 삼각화한 뒤 인덱스별로 조회해 비-중복 정점으로 펼치는 방식으로 처리했다(TinyObjWrapper와 동일한 단순화).
- `ufbx_real`이 기본적으로 `double`이라 우리 `float` 기반 `Vec3`로 변환 시 명시적 캐스팅이 필요하다 — `UfbxWrapper.cpp`에서만 처리되고 다른 코드에는 노출되지 않는다.
- C11/C++11 컴파일 시에만 atomic 기반 스레드 안전성이 보장된다(이 프로젝트의 MSVC 툴체인은 해당).

# Step 2 — Wrapper Design Draft

CLAUDE.md 원칙("외부 라이브러리는 반드시 내부 wrapper 클래스로 감싼다")을 그대로 적용.

- `ufbx.h`에 대한 직접 참조는 `src/platform/model_import/UfbxWrapper.cpp` 단 한 곳에만 존재한다.
- `UfbxWrapper.h`는 `ufbx_` 접두사의 어떤 타입도 노출하지 않고, 프로젝트 공용 타입인 `Model`/`Mesh`/`Node`만 공개 인터페이스에 사용한다.
- `ModelLoader::LoadFBX`는 `UfbxWrapper`만 알고, ufbx의 존재 자체를 모른다.
- `ufbx_scene`의 노드-메쉬 참조 구조를 그대로 순회해 씬 그래프 내부 인스턴싱을 보존한다(flatten하지 않음).

**빌드 타겟 격리**

- ufbx는 소비자용 CMakeLists.txt를 제공하지 않으므로(imgui 사례와 동일 패턴), `FetchContent`로 소스만 받아 `${ufbx_SOURCE_DIR}/ufbx.c`를 `app_lib`에 직접 추가하고, include 경로도 `app_lib`에 `PRIVATE`로만 노출한다.
- `tests` 타겟은 `ModelLoaderTest.cpp`에서 `ModelLoader.h`만 include하며, `ufbx.h`를 직접 include하지 않는다.
