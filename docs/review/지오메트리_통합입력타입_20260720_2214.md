# Code Review: 통일 Geometry 입력 타입

## Stage 1 — Quality Inspection

- [RESOLVED] 빈 `Mesh`(vertex 0개)에 대한 `Support()`/`GetBounds()` 방어적 동작(각각 `Vec3::Zero()`, 원점 퇴화 `AABB`)이 테스트로는 커버되어 있었으나 `Geometry.cpp` 파일 상단 Notes에는 명시되어 있지 않았음.
  - **[해결 방안]**
    - `Geometry.cpp` Notes에 "빈 Mesh는 Support→Vec3::Zero(), GetBounds→원점 퇴화 AABB로 방어적으로 처리(크래시 방지 목적)" 한 줄 추가 완료.
    - 재빌드 + `GeometryTest.*` 15개 케이스 재실행, 전부 통과 확인.
- [DEFERRED] (결함 아님, 트레이드오프 기록) `std::variant` 기반 설계는 OCP 관점에서 새 도형 타입 추가 시 `Geometry.h`의 타입 별칭과 `Geometry.cpp`의 `Support`/`GetBounds` 양쪽 `Overload` 세트를 전부 수정해야 함.
  - 브레인스토밍(`docs/brainstorming/충돌감지_알고리즘_20260720_2119.md` Details 6절)에서 이미 논의되고 사용자가 확정한 트레이드오프 — 조치 불필요, 향후 메모리 문제 발생 시 재검토 대상으로만 기록.

그 외 SOLID(SRP/LSP/ISP/DIP), 라이브러리 격리(`std::variant`는 표준 라이브러리라 wrapper 정책 대상 아님), 단위 테스트 커버리지(6종 도형 × Support/GetBounds + 빈 Mesh 엣지케이스, 15개), 주석 규칙(Author/설명/Input/Output/Notes/Date) 전부 이상 없음.
