# Result

- `src/ui/IUiManager.h` + `ImGuiManagerDX9`/`DX11`/`DX12`(백엔드별 폴더) 신설 — ImGui 헤더(`imgui.h`, `imgui_impl_*.h`)는 각 `.cpp` 한 곳에만 격리.
- `IUiManager`는 `NewFrame`/`Render`/`Shutdown`/`HandleWin32Message`만 순가상함수로 두고, `Initialize`는 백엔드마다 파라미터가 완전히 달라 인터페이스 밖에 둠(각 구현체가 자신에게 맞는 생성자를 가짐).
- `DirectX9Renderer`/`DirectX11Renderer`/`DirectX12Renderer`가 각각 자기 짝 `ImGuiManagerDXn`을 멤버로 소유 — ImGui 백엔드는 `config.renderer` 선택에 자동 종속되고, 별도 ImGui 관련 config 필드는 추가하지 않음(사용자 제안 반영).
- DX12는 draw call 기록에 커맨드 리스트가 필요해 `IUiManager::Render()`(무인자)로 표현 불가 — `ImGuiManagerDX12`에 인터페이스 밖 전용 `RenderWithCommandList(ID3D12GraphicsCommandList*)`를 추가하고, `DirectX12Renderer`는 구체 타입으로 직접 호출.
- `IRenderer`에 `HandleUiMessage(HWND,UINT,WPARAM,LPARAM)` 추가, `Win32Window`에 범용 `SetMessageHook` 콜백 추가(`SetResizeCallback`과 동일 패턴) — `Win32Window`는 여전히 ImGui/`IRenderer`를 모름. `main.cpp`에서 `renderer->HandleUiMessage`로 연결.
- CMake `FetchContent`로 Dear ImGui v1.92.8 확보 — 공식 CMake 타겟이 없어 필요한 `.cpp`(`imgui.cpp`/`imgui_draw.cpp`/`imgui_tables.cpp`/`imgui_widgets.cpp` + 백엔드 4개)를 `app_lib`에 직접 나열, include 경로는 `PRIVATE`로 격리.
- 이번 사이클은 "프레임워크 확보"만 목표로 확정되어 `main.cpp`에 실제 UI 위젯을 추가하지 않음 — `ImGui::NewFrame()`/`Render()`는 매 프레임 실제로 호출되지만 그 사이에 그려지는 콘텐츠는 없음(빈 `DrawData`).
- Code Review Stage 1에서 발견된 2건(DX12 `RenderFrame` null 가드 누락 — MEDIUM, `ImGuiManagerDX12::Render()` 오용 시 무응답 — LOW) 전부 그 자리에서 `[RESOLVED]` 처리 완료. 자세한 내용은 `docs/review/ImGui_UI프레임워크_20260719_1541.md` 참고.
- Code Review Stage 2(Class/Sequence 다이어그램) 완료, 같은 문서에 포함.
- Refactor Inspection은 사용자가 별도로 요청하지 않아 생략.
- 최종 검증: `cmake --build` 전체 통과 → `ctest` 72개 케이스 전부 통과(기존 58 + 신규 14: `ImGuiManagerDX9/11/12Test` 6개, `Win32WindowTest`의 `SetMessageHook` 케이스 2개) → `main.exe --renderer=directx9`/`directx11`/`directx12` 각각 수동 실행으로 1.5초간 크래시 없이 생존 확인(계획대로 시각적 ImGui 콘텐츠 없음) → `<imgui_impl_dx9/11/12.h>` 동시 include 없음, `main`/`tests` include 경로에 ImGui 헤더 미노출을 grep으로 확인.

# Notes

- 구현 중 ImGui v1.92.8의 `ImGui_ImplDX12_Init`이 계획 당시 가정한 개별 인자 시그니처가 아니라 `ImGui_ImplDX12_InitInfo` 구조체(+ `SrvDescriptorAllocFn`/`FreeFn` 콜백) 기반 API로 바뀌어 있었음을 발견 — `ImGuiManagerDX12` 생성자에 `ID3D12CommandQueue*`를 추가로 받고, 폰트 아틀라스 텍스처 하나만 쓰는 이번 사이클 범위에서는 힙의 유일한 슬롯을 그대로 내주는 최소 콜백으로 대응. DX12 폴백(`[DEFERRED]`) 없이 세 백엔드 모두 완전히 구현됨.
- `DirectX12Renderer::RenderFrame()`에 기존에 없던 `commandList->OMSetRenderTargets(...)` 호출을 추가했다 — 이전에는 `Clear`만 하고 아무것도 그리지 않아 불필요했으나, ImGui draw call이 실제로 그려질 대상을 바인딩하려면 필요했다.
- ImGui 리사이즈 대응은 별도 구현이 필요 없다 — `ImGui_ImplWin32_NewFrame()`이 매 프레임 현재 클라이언트 영역을 다시 조회해 `io.DisplaySize`를 갱신하므로, 렌더러의 기존 `OnResize`(스왑체인 버퍼 재생성)와 독립적으로 항상 최신 크기를 따라간다.
- 다음 사이클에서 실제 UI 위젯을 그리기 시작하면, DX12의 SRV 디스크립터 힙 할당자(`AllocateSrvDescriptor`/`FreeSrvDescriptor`, 현재 1개 슬롯 고정)를 여러 텍스처를 동적으로 다룰 수 있는 진짜 풀 할당자로 교체해야 한다.
