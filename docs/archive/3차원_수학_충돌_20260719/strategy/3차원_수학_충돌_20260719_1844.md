# Strategy: 기초 3차원 수학/충돌 데이터 클래스

## 적용 방식 요약

브레인스토밍에서 확정된 설계를 아래 의존 순서로 구현한다 — 공통 상수 → `Vec3` → `Quaternion` → `Matrix4x4` → `Transform` → 도형 데이터(`AABB`/`OBB`/`Sphere`/`Capsule`/`Cylinder`/`Mesh`) → 쌍별 충돌/포함 판정(`Intersections`, Tier 1 → Tier 2) → 빌드/테스트.

- `src/math/`(순수 수학)과 `src/geometry/`(도형 데이터 + 충돌 판정)로 분리하고, 둘 다 프로젝트의 다른 모듈(`config`/`renderer`/`logging` 등)을 참조하지 않는다 — 나중에 별도 저장소+submodule로 분리하기 쉽게.
- `Vec3`/`Quaternion`/`Matrix4x4`/`Transform`은 헤더 온리(연산이 짧아 인라인이 자연스러움), `geometry`의 도형은 데이터만 헤더에 두고 `Intersections`는 `.h`/`.cpp`로 분리.
- 회전은 `Quaternion`으로 표현하고, 각도 입력(축-각/오일러)은 전부 **Degree** 단위. 오일러 합성 순서: Yaw(Y)→Pitch(X)→Roll(Z).
- `Matrix4x4`는 **row-major + row-vector**(`v' = v * M`) 관례, `Transform`이 만드는 아핀 행렬 전용 역행렬만 구현(완전 일반 4x4 역행렬은 범위 밖).
- `OBB`는 `Transform`(위치+회전, scale은 항상 `(1,1,1)`) + `Vec3 halfExtents`로 표현.
- `Capsule`/`Cylinder`는 "두 끝점(Vec3 A, B) + 반지름"으로 표현.
- 쌍별 충돌/포함 판정은 `Intersections.h`의 자유 함수(유틸리티 함수)로 모은다 — 도형 클래스 자체는 데이터(+ 최소한의 편의 메서드)만 갖는다.
- 15개 쌍을 Tier 1(필수)/Tier 2(시도)/Tier 3(이번 사이클에서 시도하지 않고 바로 이월 — 사용자 승인)로 나눈다. `Mesh` 충돌과 Tier 3 항목은 커밋 리포트에 `[DEFERRED]`로 명시.
- 부동소수점 경계 비교는 공통 `constexpr float kEpsilon`(`src/math/MathConstants.h`)을 일관되게 사용.

## 구현 체크리스트

### 1. 공통 상수

- [x] `src/math/MathConstants.h` 작성 — `constexpr float kEpsilon = 1e-5f`, `constexpr float kPi = 3.14159265358979323846f`, `constexpr float DegreesToRadians(float degrees)`/`constexpr float RadiansToDegrees(float radians)`

### 2. `Vec3`

- [x] `src/math/Vec3.h` 작성 — `float x, y, z`, 기본 생성자(0,0,0), `(x,y,z)` 생성자
- [x] 연산자: `+`, `-`(이항/단항), `*`(스칼라), `/`(스칼라), `*`(컴포넌트별 `Vec3`), `==`/`!=`(정확 비교 — 근사 비교는 별도 자유 함수 `NearlyEqual(a,b,epsilon)`로 분리)
- [x] 함수: `Dot(a,b)`, `Cross(a,b)`, `Length()`, `LengthSquared()`, `Normalized() const`(길이가 `kEpsilon` 미만이면 영벡터 반환 — 0 나눗셈 방지), `static Zero()`/`static One()`
- [x] 단위 테스트: 각 연산자/함수 정상 케이스, `Normalized()`의 영벡터 예외 케이스, `Cross`/`Dot`의 직교·평행 케이스(알려진 값으로 검증)

### 3. `Quaternion`

- [x] `src/math/Quaternion.h` 작성 — `float x, y, z, w`, 기본 생성자는 단위 회전(0,0,0,1)
- [x] `static Identity()`, `static FromAxisAngle(const Vec3& axis, float angleDegrees)`, `static FromEulerDegrees(float pitchDegrees, float yawDegrees, float rollDegrees)`(Yaw→Pitch→Roll 합성)
- [x] `operator*(Quaternion, Quaternion)`(회전 합성), `Normalized() const`, `Conjugate() const`, `Inverse() const`, `Vec3 Rotate(const Vec3&) const`, `Length() const`
- [x] 단위 테스트: 단위 회전이 벡터를 바꾸지 않는지, 알려진 축(X/Y/Z)의 90°/180° 회전이 기대값과 일치하는지, 오일러 합성 순서(Yaw→Pitch→Roll)가 문서화된 대로 동작하는지, 정규화/역원 검증

### 4. `Matrix4x4`

- [x] `src/math/Matrix4x4.h/.cpp` 작성 — `float m[4][4]`(row-major)
- [x] `static Identity()`, `static FromTRS(const Vec3& position, const Quaternion& rotation, const Vec3& scale)`
- [x] `operator*(Matrix4x4, Matrix4x4)`, `Vec3 TransformPoint(const Vec3&) const`(이동 포함), `Vec3 TransformDirection(const Vec3&) const`(이동 미포함), `Transpose() const`, `InverseAffine() const`(아핀 전용 — 회전 3x3 전치 + 이동 재계산)
- [x] 단위 테스트: 단위 행렬 곱/변환이 항등, `FromTRS`로 만든 행렬이 알려진 점을 기대한 좌표로 옮기는지, `TransformPoint` vs `TransformDirection`이 이동 성분을 다르게 다루는지, `InverseAffine`으로 왕복(`M * InverseAffine(M) ≈ Identity`) 검증

### 5. `Transform`

- [x] `src/math/Transform.h` 작성 — `Vec3 position`, `Quaternion rotation`(기본값 `Identity()`), `Vec3 scale`(기본값 `(1,1,1)`)
- [x] `Matrix4x4 ToMatrix() const`(`Matrix4x4::FromTRS` 위임), `Vec3 GetAxisX/Y/Z() const`(`rotation.Rotate(단위벡터)`)
- [x] 단위 테스트: 기본 `Transform`의 `ToMatrix()`가 단위 행렬인지, 특정 회전에서 `GetAxisX/Y/Z()`가 기대한 축과 일치하는지

### 6. 도형 데이터 클래스

- [x] `src/geometry/AABB.h` — `Vec3 min, max` + `Vec3 Center() const`, `Vec3 Extents() const`(half-size)
- [x] `src/geometry/OBB.h` — `Transform transform`, `Vec3 halfExtents` + `Vec3 GetAxis(int index) const`(0,1,2 → X/Y/Z)
- [x] `src/geometry/Sphere.h` — `Vec3 center`, `float radius` (데이터만)
- [x] `src/geometry/Capsule.h` — `Vec3 pointA, pointB`, `float radius` (데이터만)
- [x] `src/geometry/Cylinder.h` — `Vec3 pointA, pointB`, `float radius` (데이터만)
- [x] `src/geometry/Mesh.h` — `std::vector<Vec3> vertices`, `std::vector<uint32_t> indices`(삼각형 리스트) — 데이터만, 충돌 로직 없음
- [x] 단위 테스트: `AABB::Center/Extents`, `OBB::GetAxis`(알려진 회전에서 기대 축과 일치)만 — 나머지는 순수 데이터라 테스트 대상 없음(프로젝트 내 `DataRecord` 등 순수 데이터 구조체와 동일 관례)

### 7. `Intersections` — Tier 1 (필수)

- [x] `src/geometry/Intersections.h/.cpp` 작성
- [x] `bool Contains(const AABB&, const Vec3& point)`
- [x] `bool Contains(const OBB&, const Vec3& point)`(점을 OBB 로컬 공간으로 변환 후 각 축 half-extent와 비교)
- [x] `bool Intersects(const AABB&, const AABB&)` + `std::optional<AABB> IntersectionRegion(const AABB&, const AABB&)`(겹치는 영역, 안 겹치면 `nullopt`)
- [x] `bool Intersects(const Sphere&, const Sphere&)`
- [x] `bool Intersects(const Sphere&, const AABB&)` (+ 인자 순서 반대 오버로드)
- [x] `bool Intersects(const Sphere&, const OBB&)` (+ 반대 오버로드)
- [x] `bool Intersects(const AABB&, const OBB&)` (+ 반대 오버로드) — AABB를 축정렬 OBB로 취급해 SAT 재사용
- [x] `bool Intersects(const OBB&, const OBB&)` — SAT(분리축 정리), 15개 후보 축(각자 3개 + 축끼리 외적 9개)
- [x] `bool Intersects(const Sphere&, const Capsule&)` (+ 반대 오버로드)
- [x] `bool Intersects(const Capsule&, const Capsule&)` — 선분-선분 최단거리(Ericson *Real-Time Collision Detection* 표준 알고리즘) 후 반지름 합과 비교
- [x] 단위 테스트: 각 함수마다 겹침/안 겹침/경계(接) 케이스 최소 3종

### 8. `Intersections` — Tier 2 (시도, 막히면 단순화 허용)

- [x] `bool Intersects(const Capsule&, const AABB&)` (+ 반대 오버로드)
  - **구현 중 변경**: 계획했던 "선분-박스 최단거리 닫힌 형태 공식" 대신, 선분과 볼록 도형(AABB/OBB) 사이를 번갈아 투영(alternating projection)하는 반복 기법으로 구현 — 둘 다 볼록 집합이라 8회 반복이면 충분히 수렴한다. Tier 2의 "닫힌 형태 해 대신 단순화 허용" 방침 범위 내의 구현.
- [x] `bool Intersects(const Capsule&, const OBB&)` (+ 반대 오버로드) — 위와 동일한 alternating-projection 기법을 `ClosestPointOnOBB`에 적용
- [x] `bool Intersects(const Sphere&, const Cylinder&)` (+ 반대 오버로드) — 축 선분 최단거리 + 캡(평평한 원판, 반지름 안쪽은 평면까지 수직거리·바깥쪽은 테두리 원까지 거리) 케이스 처리
- [x] 단위 테스트: 각 함수마다 겹침/안 겹침/경계 케이스
- [x] **결과: Tier 2 전부 구현 완료, 제외된 항목 없음** — 계획했던 "과도하게 복잡해지면 제외" 폴백은 사용하지 않음.

## 최종 승인 및 검증 기준

- CMake로 `main`, `tests` 타겟이 모두 정상 컴파일·링크된다.
- `tests` 타겟의 모든 케이스가 통과한다.
- Tier 1의 모든 쌍(AABB/OBB point 포함, AABB-AABB 교차+공통공간, Sphere-Sphere, Sphere-AABB, Sphere-OBB, AABB-OBB, OBB-OBB, Sphere-Capsule, Capsule-Capsule)이 구현되고 테스트로 검증된다.
- Tier 2는 최대한 구현하되, 제외된 항목이 있다면 커밋 리포트에 `[DEFERRED]`로 명시된다 — **실제로는 3쌍 전부 구현 완료, 제외된 항목 없음.**
- Tier 3과 `Mesh` 충돌은 이번 사이클에서 구현하지 않고 커밋 리포트에 `[DEFERRED]`로 명시된다.
- `src/math`/`src/geometry`가 프로젝트의 다른 모듈(`config`/`renderer`/`logging` 등)을 참조하지 않는다(향후 submodule 분리를 위한 전제 조건, 코드 리뷰로 확인).
- 회전 각도 입력이 일관되게 Degree 단위로 노출된다(코드 리뷰로 확인).
- 신규 작성된 모든 함수/클래스에 CLAUDE.md 주석 규칙(Author / 설명 / Input / Output / Notes / Date)이 반영되어 있다.
