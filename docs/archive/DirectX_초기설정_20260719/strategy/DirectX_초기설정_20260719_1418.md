# Strategy: DirectX 초기 설정 및 빈 화면 출력

## 적용 방식 요약

브레인스토밍에서 확정된 설계를 아래 순서로 코드에 반영한다 — 선택 구조(enum/파서) → 플랫폼(윈도우) → 렌더러 인터페이스 → 버전별 구현(DX9/DX11/DX12) → 진입점 배선 → 빌드/테스트.

- `RendererBackend`을 `{DirectX9, DirectX11, DirectX12, OpenGL}`로 확장하고 기존 `"directx"` 토큰은 완전히 제거한다.
- `Win32Window`(신규, `src/platform/`)를 렌더러와 독립적으로 만들고, `main()`이 하나 생성해 선택된 렌더러에 `HWND`를 전달한다.
- `IRenderer`에 `Initialize(HWND,width,height)`/`RenderFrame()`/`OnResize(width,height)`/`Shutdown()` 4개만 추가한다 — 그 이상 확장하지 않는다.
- `DirectX9Renderer`/`DirectX11Renderer`/`DirectX12Renderer`는 각각 `<d3d9.h>`/`<d3d11.h>`/`<d3d12.h>`만 아는 파일로 완전히 분리한다. 단, 세 렌더러 모두 같은 정적 라이브러리(`app_lib`) 타겟으로 컴파일되므로, 최종 링크 단계에서는 `app_lib`이 `d3d9.lib`/`d3d11.lib`/`d3d12.lib`/`dxgi.lib`를 모두 링크하게 된다 — 헤더/소스 수준의 격리이지, 별도 실행 파일로 분리한다는 의미가 아니다.
- 디바이스 상태(디바이스/컨텍스트/스왑체인/RTV, DX12는 커맨드 큐/할당자/리스트/펜스)는 각 렌더러의 영속 멤버로 보유한다 — 다음 사이클에서 draw call 관련 메서드가 추가돼도 이 상태를 재사용할 수 있게 한다.
- DX12의 커맨드 할당자/리스트 개수는 하드코딩된 리터럴 `1`이 아니라 이름 있는 상수(`kFrameCount` 등)로 뽑아, 이후 멀티스레드 기록으로 확장할 여지를 구조적으로 남긴다(실제 멀티스레드 구현은 이번 사이클 범위 아님).

## 구현 체크리스트

### 1. `RendererBackend` / 파서 확장

- [x] `RendererBackend.h`를 `{DirectX9, DirectX11, DirectX12, OpenGL}`로 변경
- [x] `RendererBackendParser.cpp`의 `kDirectXName`/`kOpenGLName` 상수를 `kDirectX9Name = "directx9"`, `kDirectX11Name = "directx11"`, `kDirectX12Name = "directx12"`, `kOpenGLName = "opengl"`로 갱신
- [x] `RendererBackendParserTest`에 `"directx9"` 케이스 추가, 기존 `"directx"` 관련 케이스 제거
- [x] `LaunchConfigParserTest`/`ConfigManagerTest`의 `RendererBackend::DirectX` 참조를 `DirectX11`(혹은 테스트 의도에 맞는 값)로 갱신
- [x] `AppConfig.h`의 `renderer` 기본값을 `RendererBackend::DirectX11`로 유지(기존 DirectX 기본값 취지 계승)

### 2. `src/platform/Win32Window`

- [x] `src/platform/` 디렉토리 생성
- [x] `Win32Window.h` 작성 — 생성자(`width`, `height`, `title`, `fullscreen`), `HWND Handle() const`, `bool PumpMessages()`, `void SetResizeCallback(std::function<void(int,int)>)`
- [x] `Win32Window.cpp` 작성 — `RegisterClassEx`/`CreateWindowEx`(`WS_OVERLAPPEDWINDOW` 스타일로 리사이즈 가능하게), 소멸자에서 `DestroyWindow`/`UnregisterClass`
- [x] `WM_SIZE` 처리 — 등록된 리사이즈 콜백 호출, 크기가 0(최소화)인 경우는 콜백 호출 생략
- [x] `WM_DESTROY`/`WM_CLOSE` 처리 — `PostQuitMessage(0)`, `PumpMessages()`가 `WM_QUIT` 수신 시 `false` 반환
- [x] borderless fullscreen 지원 — 생성 시 `fullscreen=true`면 `WS_POPUP` 스타일 + 모니터 해상도로 생성(`GetSystemMetrics` 또는 `MonitorFromWindow`+`GetMonitorInfo` 사용)
- [x] 단위 테스트: `Win32Window` 생성 후 `Handle()`이 유효한 `HWND`를 반환하는지, 소멸 시 예외 없이 정리되는지 검증 (화면에 보이지 않는 오프스크린 생성도 가능 — `ShowWindow` 호출 여부와 무관하게 `HWND` 자체는 생성됨)

### 3. `IRenderer` 인터페이스 확장

- [x] `IRenderer.h`에 `Initialize(HWND windowHandle, int width, int height)`, `RenderFrame()`, `OnResize(int width, int height)` 순가상함수 추가 (기존 `Initialize()`/`Shutdown()` 시그니처 변경 포함)
- [x] `OpenGLRenderer.h/.cpp`를 새 시그니처에 맞춰 갱신 — 전부 no-op 스텁 유지 (이번 사이클 범위 아님)
- [x] `RendererFactoryTest`/`OpenGLRenderer` 관련 기존 테스트를 새 시그니처에 맞춰 갱신

### 4. `AppConfig` — 창 제목 필드 추가

- [x] `AppConfig.h`에 `std::string windowTitle` 필드 추가, 기본값은 이름 있는 상수(`kDefaultWindowTitle = "World of Tank Imitation"`)로 초기화
- [x] `ConfigFields.h`에 `kWindowTitle = "windowTitle"` 상수 추가
- [x] `ConfigManager.cpp`의 `LoadOrDefault`에 `windowTitle` 필드를 `DataRecordAccess::GetStringOr`로 읽는 로직 추가
- [x] `ConfigManagerTest`에 `windowTitle` override 테스트 케이스 추가

### 5. `DirectX9Renderer` (`src/renderer/`, `<d3d9.h>` 전용)

- [x] `DirectX9Renderer.h/.cpp` 작성 — `IDirect3D9`/`IDirect3DDevice9` 멤버 보유
- [x] `Initialize`: `Direct3DCreate9` → `D3DPRESENT_PARAMETERS` 구성(`hDeviceWindow`=전달받은 HWND, `BackBufferWidth/Height`) → `CreateDevice`
- [x] `RenderFrame`: `Clear` → `Present`
- [x] `OnResize`: `IDirect3DDevice9::Reset`으로 백버퍼 재생성 (크기 0은 무시)
- [x] `Shutdown`: COM 인터페이스 해제(스마트 포인터 소멸에 위임 가능)
- [x] 단위 테스트: `D3DDEVTYPE_NULLREF`로 디바이스 생성 성공 여부 검증 (GPU 불필요)
  - **구현 중 변경**: DX9의 REF/NULLREF 소프트웨어 디바이스는 레거시 DirectX SDK 컴포넌트가 있어야 안정적으로 동작해(설치 안 된 환경에서는 `D3DERR_NOTAVAILABLE`로 실패할 수 있음), 이번 사이클에서는 `D3DDEVTYPE_HAL`(실제 하드웨어)로 `Initialize()`를 직접 호출해 검증하는 방식으로 대체함. 이 개발 환경의 실제 GPU/드라이버로 검증 완료.

### 6. `DirectX11Renderer` (`src/renderer/`, `<d3d11.h>`/`<dxgi.h>`/`<wrl/client.h>` 전용)

- [x] `DirectX11Renderer.h/.cpp` 작성 — `ComPtr<ID3D11Device>`/`ComPtr<ID3D11DeviceContext>`/`ComPtr<IDXGISwapChain>`/`ComPtr<ID3D11RenderTargetView>` 멤버 보유
- [x] `Initialize`: `D3D11CreateDeviceAndSwapChain`(하드웨어 드라이버 타입, feature level 11_0) → RTV 생성
- [x] `RenderFrame`: `ClearRenderTargetView` → `Present`
- [x] `OnResize`: RTV 해제 → `IDXGISwapChain::ResizeBuffers` → RTV 재생성 (크기 0은 무시)
- [x] `Shutdown`: ComPtr 해제(자동)
- [x] 단위 테스트: `D3D_DRIVER_TYPE_WARP`로 디바이스 생성 성공 여부 검증
  - **구현 중 변경**: `DirectX11Renderer`에 테스트 전용 `forceWarp` 생성자 파라미터(기본 false)를 추가 — production에서는 하드웨어 우선 시도 후 실패 시 WARP로 자동 폴백(실사용 목적의 견고성 기능), 테스트에서는 `forceWarp=true`로 GPU 유무와 무관하게 WARP 경로를 결정적으로 검증.

### 7. `DirectX12Renderer` (`src/renderer/`, `<d3d12.h>` 전용)

- [x] `DirectX12Renderer.h/.cpp` 작성 — 디바이스/커맨드 큐/커맨드 할당자·리스트(개수는 `kFrameCount` 상수화)/디스크립터 힙(RTV)/펜스 멤버 보유
- [x] `Initialize`: `D3D12CreateDevice` → 커맨드 큐 생성 → `IDXGIFactory`로 스왑체인 생성 → RTV 디스크립터 힙 + 각 버퍼 RTV 생성 → 커맨드 할당자/리스트/펜스 생성
- [x] `RenderFrame`: 커맨드 리스트 리셋 → 리소스 배리어(Present→RenderTarget) → `ClearRenderTargetView` → 리소스 배리어(RenderTarget→Present) → `Close` → `ExecuteCommandLists` → `Present` → 펜스 Signal/Wait(GPU 동기화)
- [x] `OnResize`: 펜스로 GPU idle 대기 → RTV 해제 → `ResizeBuffers` → RTV 재생성 (크기 0은 무시)
- [x] `Shutdown`: GPU idle 대기 후 ComPtr 해제
- [x] 단위 테스트: `IDXGIFactory::EnumWarpAdapter` + `D3D12CreateDevice`로 디바이스 생성 성공 여부 검증
  - DX11과 동일하게 `forceWarp` 생성자 파라미터로 테스트에서 WARP 경로를 결정적으로 검증. `kFrameCount`는 스왑체인 버퍼 개수(`kBackBufferCount=2`, flip-model 최소 요구사항)와 커맨드 리스트 개수(`kCommandListCount=1`, 확장성 가이드라인)로 분리해 명명함(원래 체크리스트의 `kFrameCount` 단일 상수 계획에서 구체화).

### 8. `RendererFactory` / `main()` 배선

- [x] `RendererFactory.cpp`에 `DirectX9`/`DirectX11`/`DirectX12` 3개 분기 추가(기존 `DirectX` 분기 제거)
- [x] `main.cpp`: `ConfigManager`로 `AppConfig` 로드 → `Win32Window` 생성(`appConfig.width/height/windowTitle/fullscreen`) → `RendererFactory::Create`로 렌더러 생성 → `renderer->Initialize(window.Handle(), width, height)` → `window.SetResizeCallback(...)`로 `renderer->OnResize` 연결 → `while (window.PumpMessages()) { renderer->RenderFrame(); }` → `renderer->Shutdown()`

- [x] `main`, `tests` 타겟 전체 빌드 통과 확인
- [x] `tests` 타겟 전체 케이스 통과 확인 (`ctest`)
- [x] `/verify`로 수동 실행 확인: `--renderer=directx9`/`directx11`/`directx12` 각각 빈 창이 뜨는지, 창 테두리 드래그로 크기 조절되는지, `config.json`의 `fullscreen: true`로 전체화면 진입하는지

## 최종 승인 및 검증 기준

- CMake로 `main`, `tests` 타겟이 모두 정상 컴파일·링크된다.
- `tests` 타겟의 모든 케이스(백엔드 파서, `Win32Window` 생성, DX9/DX11/DX12 각각의 NULLREF/WARP 디바이스 생성)가 통과한다.
- `main.exe --renderer=directx9`, `--renderer=directx11`, `--renderer=directx12` 각각 실행 시 빈 창이 크래시 없이 뜬다(수동 확인).
- 창 테두리를 드래그해 크기를 조절해도 크래시 없이 화면이 유지된다(수동 확인).
- `config.json`의 `fullscreen: true`로 전체화면 모드가 적용된다(수동 확인).
- `<d3d9.h>`/`<d3d11.h>`/`<d3d12.h>`를 동시에 include하는 파일이 없다 (grep으로 확인).
- `DirectX9Renderer`/`DirectX11Renderer`/`DirectX12Renderer`/`Win32Window`가 각각 단일 책임만 가지는지 코드 리뷰로 확인한다 (SRP).
- 신규 작성된 모든 함수/클래스에 CLAUDE.md 주석 규칙(Author / 설명 / Input / Output / Notes / Date)이 반영되어 있다.
