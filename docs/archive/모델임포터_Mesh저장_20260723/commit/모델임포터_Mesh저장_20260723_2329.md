# Commit — 모델 Importer (Mesh 읽기/저장)

## 구현 결과 요약

`src/model_import/`에 OBJ/FBX/GLTF/GLB 모델 임포트 기능을 구현했다.

- 공통 데이터 구조: `ModelMesh`(지오메트리) / `Node`(씬 그래프) / `Model`(파일 하나의 로드 결과).
- 포맷별 Importer: `TinyObjWrapper`(tinyobjloader v1.0.7) / `UfbxWrapper`(ufbx v0.23.0) / `CgltfWrapper`(cgltf v1.15), `ModelLoader` 네임스페이스 정적 함수로 노출.
- 캐시 정책 전략 패턴: `IMeshCachePolicy` + `RefCountingCachePolicy`/`LruCachePolicy`/`HotReloadCachePolicy`.
- 파일 변경 감지: `IFileChangeDetector` + `Win32FileWatcher`(`ReadDirectoryChangesW`, 전용 워커 스레드).
- 기하 합동 중복 제거: `IMeshDeduplicator` + `NaiveSignatureDeduplicator`(근사 휴리스틱).
- 오케스트레이션: `MeshManager` (정책 주입 + opt-in 캐싱 + opt-in 중복 제거).
- `docs/dependency/` 3종 작성, `docs/algorithm/10_Bone_가중치_스키닝.md` 학습 노트 작성.
- `ctest` 267개 전체 통과.

## 구현 중 발견 및 해결한 문제

- [CRITICAL] `src/model_import/Mesh.h`가 정의한 전역 `struct Mesh`가 기존 충돌 감지용 `src/geometry/Mesh.h`의 전역 `struct Mesh`와 이름이 충돌(One Definition Rule 위반)해, 두 헤더가 같은 바이너리에 함께 링크되면 메모리 레이아웃이 꼬여 임의의 지점에서 접근 위반(SEH 0xC0000005)이 발생했다.
  - 증상이 특이했다 — 독립 실행 파일이나 신규 테스트 파일만 있는 최소 gtest 바이너리에서는 재현되지 않고, 기존 수학/충돌 테스트 파일들과 같은 바이너리로 링크되었을 때만 재현되어 원인 파악에 이진 탐색이 필요했다.
  - [RESOLVED] 신규 타입을 `ModelMesh`로 이름 변경(`Mesh.h` → `ModelMesh.h`)해 충돌 감지 모듈과 완전히 분리했다. 재빌드 후 `ctest` 267/267 통과로 확인.
- [HIGH] `Win32FileWatcher`가 생성자에서 감시 스레드를 시작만 하고 실제 `ReadDirectoryChangesW` 호출이 걸릴 때까지 기다리지 않아, 생성자 직후 곧바로 파일을 수정하면 "아직 감시가 안 걸린" 상태라 변경 알림을 놓치는 경쟁 조건이 있었다.
  - [RESOLVED] 워커 스레드가 첫 `ReadDirectoryChangesW` 호출을 실제로 건 시점에 이벤트(`m_readyEvent`)를 신호하고, 생성자가 그 이벤트를 기다린 뒤 반환하도록 수정. 관련 단위 테스트 통과로 확인.
- [MEDIUM] `CgltfWrapper`의 `has_matrix` 노드 처리가 미러링(반사, 음수 행렬식)을 구분하지 못함.
  - [RESOLVED] 코드 리뷰 단계에서 발견, 클래스 주석에 한계를 명시(코드 동작 변경 없음 — 이번 사이클 스코프 밖으로 확인된 한계).
- [LOW] `NaiveSignatureDeduplicator`의 시그니처 registry에 축출 정책이 없어 무한정 쌓임.
  - [RESOLVED] 클래스 주석에 한계 명시.
- [LOW] `Win32FileWatcher` 인스턴스 하나는 생성 시점에 고정된 단일 루트 디렉터리만 감시.
  - [RESOLVED] 클래스 주석에 제약 명시.
