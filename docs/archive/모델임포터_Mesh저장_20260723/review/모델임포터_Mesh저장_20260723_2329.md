# Code Review — 모델 Importer (Mesh 읽기/저장)

## Stage 1 — Quality Inspection

### SOLID 원칙

- Single Responsibility — 준수. 라이브러리별 Wrapper(파싱), `ModelLoader`(퍼사드), 캐시 정책(수명 관리), `IMeshDeduplicator`(정체성 판단), `MeshManager`(오케스트레이션)로 책임이 분리되어 있다.
- Open/Closed — 준수. 새 캐시 정책/디텍터/디듀플리케이터 추가 시 기존 클래스를 수정할 필요가 없다(전부 인터페이스 기반).
- Liskov Substitution — 준수. `IMeshCachePolicy` 세 구현체 모두 계약(캐시 미스 시 nullptr, Unload는 정책 무관 항상 동작)을 동일하게 지킨다.
- Interface Segregation — 준수. 각 인터페이스가 1~3개의 최소 메서드만 노출한다.
- Dependency Inversion — 준수. `MeshManager`/`HotReloadCachePolicy`는 구체 클래스가 아니라 인터페이스에만 의존한다.

### 라이브러리 격리

- `tiny_obj_loader.h`/`ufbx.h`/`cgltf.h` 직접 include가 각각의 Wrapper `.cpp` 한 곳에만 존재함을 grep으로 확인.
- 세 라이브러리 모두 `app_lib`에 `PRIVATE`로만 연결되어 `main`/`tests` 타겟 include 경로에 노출되지 않음을 확인.

### 단위 테스트

- 구현된 기능(포맷별 Importer, 캐시 정책 4종, 디텍터, 디듀플리케이터, MeshManager 오케스트레이션)에 대응하는 테스트가 모두 존재한다.
- `ctest` 267개 전체 통과, 기존 테스트 대비 회귀 없음.

### 주석 규칙

- 신규 헤더 파일 전체(`ModelMesh.h`/`Node.h`/`Model.h`/`ModelLoader.h`/`TinyObjWrapper.h`/`UfbxWrapper.h`/`CgltfWrapper.h`/`IMeshCachePolicy.h`/`RefCountingCachePolicy.h`/`LruCachePolicy.h`/`HotReloadCachePolicy.h`/`IFileChangeDetector.h`/`Win32FileWatcher.h`/`IMeshDeduplicator.h`/`NaiveSignatureDeduplicator.h`/`MeshManager.h`/`Vec2.h`)에 Author/Description/Input/Output/Notes/Date 형식 주석이 존재함을 확인.

### 발견된 이슈

- [MEDIUM] `CgltfWrapper`의 `has_matrix` 노드 처리가 미러링(반사, 음수 행렬식)을 구분하지 못해 반사가 포함된 노드를 반사가 빠진 잘못된 회전으로 조용히 변환한다.
  - 이번 사이클은 "shear 없음" 단순화까지만 스코프였고, 반사 판정(행렬식 부호 확인)까지 포함하면 스코프가 늘어난다.
  - **[해결 방안]**
    - 코드 주석에 이 한계를 명시적으로 기록해, 향후 이런 노드를 가진 에셋에서 문제가 생기면 원인을 바로 추적할 수 있게 한다.
  - [RESOLVED] `CgltfWrapper.h`/`.cpp`의 Notes에 한계 명시 완료.
- [LOW] `NaiveSignatureDeduplicator`의 시그니처 registry에 축출(eviction) 정책이 없어 프로세스 생애 동안 계속 쌓인다.
  - 이번 사이클의 목적이 정확도/성능이 아니라 인터페이스 경계 확정이라 의도된 단순화이지만, 문서화가 부족했다.
  - **[해결 방안]**
    - 클래스 주석에 한계를 명시한다. 실사용 규모가 커지면 별도 사이클에서 재검토한다.
  - [RESOLVED] `NaiveSignatureDeduplicator.h` Notes에 명시 완료.
- [LOW] `Win32FileWatcher` 인스턴스 하나는 생성 시점에 고정된 단일 루트 디렉터리만 감시하므로, 여러 디렉터리에 흩어진 파일의 핫리로드를 조합하려면 공통 상위 폴더를 고르거나 워처를 여러 개 둬야 한다.
  - **[해결 방안]**
    - 클래스 주석에 이 제약을 명시해 향후 `MeshManager` 구성 시 실수를 방지한다.
  - [RESOLVED] `Win32FileWatcher.h` Notes에 명시 완료.

이 세 항목 모두 이번 Task에서 개발한 범위 내의 사안이라 즉시 해결(주석 보강) 후 재빌드·재테스트로 회귀 없음을 확인했다(`ctest` 267/267 통과).
