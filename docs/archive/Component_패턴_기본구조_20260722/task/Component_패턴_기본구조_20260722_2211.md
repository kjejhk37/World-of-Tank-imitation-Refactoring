> 브레인스토밍 단계 초반에는 "ECS 아키텍처"라는 이름으로 논의를 시작했으나,

## Purpose

IEntity, IComponent 인터페이스를 정의하고,
Entity가 Component를 저장·조회할 수 있는 기본 Component 패턴(Entity-Component 아키텍처)을 구현한다.

## User Draft

- IEntity, IComponent 인터페이스를 둔다.
- Entity는 Component를 저장하며, 저장된 Component를 조회할 수 있어야 한다.

아래는 브레인스토밍 단계에서 사용자와 함께 확정할 open question이다.

1. Component 저장 방식 (`type_index` 기반 map / 비트마스크 / sparse set 등)
2. Entity를 단순 ID(정수) 핸들로 둘지, 클래스로 둘지
3. System을 이번 범위에 포함할지, 이번엔 Entity/Component 저장·조회까지만 다룰지
4. 이 구조를 어디에 적용할 계획인지 (예: 탱크/게임 오브젝트 대체용인지, 별도 독립 모듈인지)
