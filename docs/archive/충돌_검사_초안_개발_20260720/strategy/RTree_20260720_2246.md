# Strategy: R-Tree (로드맵 5번)

## 적용 방식

broad-phase 알고리즘. BVH/SAP와 같은 문제를 푸는 세 번째 대안 — BVH는 한 번에 top-down으로 빌드하는 정적 구조인 반면, R-Tree는 삽입(`Insert`)을 통해 점진적으로 자라는 동적 구조라는 점이 본질적 차이(브레인스토밍에서 논의한 R-Tree의 특징). `GetBounds()`만 사용, 다른 알고리즘 모듈을 참조하지 않는다.

### 파일 구성 (`src/collision/rtree/`)

- `RTree.h`/`.cpp` — `class RTree { RTree() = default; explicit RTree(const std::vector<Geometry>&); void Insert(const Geometry&); std::vector<std::pair<size_t,size_t>> FindOverlappingPairs() const; }`.

### 알고리즘 개요 (Guttman의 고전 R-Tree, 1984)

- 노드당 최대 항목 수(`kMaxEntries=4`), 최소 항목 수(`kMinEntries=2`) 고정.
- **삽입**: 리프까지 내려가며 각 단계에서 "새 항목을 포함하도록 넓혔을 때 부피 증가가 가장 작은" 자식을 선택(`ChooseSubtree`). 리프에 항목을 넣은 뒤 항목 수가 `kMaxEntries`를 넘으면 분할(quadratic split: 가장 "낭비"가 큰 두 항목을 시드로 잡고, 나머지를 부피 증가가 작은 쪽으로 하나씩 배정). 분할이 루트까지 전파되면 새 루트를 만들어 트리 높이가 1 늘어난다.
- **쿼리(자기 자신과의 충돌)**: 리프 노드는 내부 항목끼리 전부 쌍 비교(브루트포스, 노드당 최대 4개라 저렴). 내부 노드는 각 자식에 대해 재귀 `SelfCollide` + 서로 다른 자식 쌍마다 `CollectOverlaps`(형제 노드는 항상 같은 높이라는 R-Tree 불변식 덕분에 BVH의 self-collide 패턴을 N-ary로 일반화 가능).

### 테스트 전략

BVH/SAP 테스트와 같은 배치로 동일한 논리적 결과를 검증(세 모듈이 독립적으로 같은 정답에 도달하는지). 추가로 `kMaxEntries`(4)보다 많은 객체를 넣어 분할이 실제로 일어나는 경로도 검증하고, 생성자 이후 `Insert()`로 객체를 추가해도 새 겹침이 정상 검출되는지(R-Tree만의 특징) 확인한다.
