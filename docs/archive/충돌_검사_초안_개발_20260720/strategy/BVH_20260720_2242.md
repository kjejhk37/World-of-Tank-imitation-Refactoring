# Strategy: BVH (로드맵 4번)

## 적용 방식

broad-phase 알고리즘. Sweep and Prune과 같은 문제(다수 Geometry 중 겹칠 가능성이 있는 후보 쌍 추리기)를 트리 구조로 푼다. `GetBounds()` 자유 함수만 사용, 다른 알고리즘 모듈(GJK/EPA/SAP)을 참조하지 않는다.

SAP과의 차이(교육적으로 의미 있는 대조): SAP은 매 쿼리마다 처음부터 정렬하는 1회성 계산인 반면, BVH는 트리를 한 번 빌드(`Bvh` 생성자)해두고 여러 번 쿼리(`FindOverlappingPairs()`)할 수 있는 자료구조라는 점이 본질적 차이 — 그래서 이번 모듈은 자유 함수가 아니라 클래스로 설계한다.

### 파일 구성 (`src/collision/bvh/`)

- `Bvh.h`/`.cpp` — `class Bvh { explicit Bvh(const std::vector<Geometry>&); std::vector<std::pair<size_t,size_t>> FindOverlappingPairs() const; }`.

### 알고리즘 개요

- **빌드**: 각 객체의 `GetBounds()`로 AABB를 구하고, top-down으로 재귀 분할한다. 분할할 원소가 2개 이상이면 현재 범위의 결합 AABB에서 가장 넓은 축을 골라, 그 축의 중심점 기준 중앙값으로 좌/우로 나눈다(median split — SAH 등 분할 품질 최적화는 이번 사이클 범위 밖). 리프는 원소 1개.
- **쿼리(자기 자신과의 충돌)**: `SelfCollide(node)` — 리프면 종료, 아니면 `SelfCollide(left)` + `SelfCollide(right)` + `CollectOverlaps(left, right)`(교차 쌍만) 재귀 호출 — 이 3분할로 중복/누락 없이 모든 쌍을 정확히 한 번씩 검사한다(Bullet 등에서 쓰는 표준 self-collide 패턴). `CollectOverlaps(a,b)`는 두 서브트리의 AABB가 겹칠 때만 재귀하고, 리프-리프 쌍에서 기존 `Intersects(AABB,AABB)`(Intersections.h)를 재사용해 최종 판정한다.

### 테스트 전략

Sweep and Prune 테스트와 유사한 배치(겹침 여러 개 + 완전히 떨어진 객체)로 결과가 SAP과 동일한 논리적 결과를 내는지 검증 — 단, 두 모듈은 서로 독립이라 코드 재사용/직접 비교 코드는 없고 각자 기대값을 하드코딩한다.
