# Strategy: MPR (로드맵 8번, 참고용 낮은 우선순위)

브레인스토밍에서 "GJK/EPA와 비교용, 낮은 우선순위"로 분류된 항목 — 이번 사이클은 충돌 여부(boolean)만 다루고, EPA에 준하는 정밀한 침투 깊이 계산은 범위 밖으로 둔다(GJK+EPA 사이클에서 이미 깊이 계산은 확보됨).

## 적용 방식

narrow-phase 알고리즘. GJK와 같은 문제(두 Geometry의 충돌 여부)를 다른 방식(포탈 정제, Portal Refinement)으로 푼다. `Support()` 자유 함수만 사용, GJK/EPA 등 다른 알고리즘 모듈을 참조하지 않는다(독립성 — GJK와 개념은 비교 대상이지만 코드는 완전히 별개로 새로 작성).

### 파일 구성 (`src/collision/mpr/`)

- `Mpr.h`/`.cpp` — `bool Intersects(const Geometry& a, const Geometry& b);`

### 알고리즘 개요 (XenoCollide / Snethen 방식)

1. 내부 기준점 `v0`(민코프스키 차의 대략적인 중심 — `GetBounds(a).Center() - GetBounds(b).Center()`로 근사).
2. `v0`에서 원점을 향하는 방향 `d = -v0`로 첫 포탈 정점 `v1` 탐색, `d`에 수직인 방향으로 두 번째 정점 `v2` 탐색 — 이 시점에 각 지지점이 원점을 지나치지 못하면(분리축 발견) 즉시 비충돌 반환(GJK의 조기 종료와 같은 개념).
3. `v0-v1-v2` 포탈이 광선 `d`를 각도상 감싸도록(원점 방향이 두 변 사이에 오도록) 보정.
4. 포탈을 반복적으로 확장: 포탈 평면 법선 방향으로 새 지지점 `v3`를 구해 개선이 없으면 수렴(그 포탈이 경계에 근접) — 원점이 최종 포탈의 안쪽(v0 쪽)에 있는지로 충돌 여부를 판정. 개선이 있으면 `v1`/`v2` 중 광선 기준으로 맞는 쪽을 `v3`로 교체하고 반복.

### 테스트 전략

GJK/EPA 사이클과 동일한 Sphere-Sphere/AABB-AABB 분리·충돌 케이스로 boolean 결과만 비교(깊이 값은 검증하지 않음 — 이번 모듈 범위 밖).

## 알려진 한계 (참고 기록)

구현 중 Sphere-OBB 조합으로 추가 검증을 시도한 결과, OBB처럼 지지 함수가 한 옥탄트 전체에서 같은 모서리를 반환하는 평평한(polytope) 도형에서는 포탈 정제가 수렴하지 않고 몇 개의 정점 사이를 순환하는 경우를 발견했다. GJK/EPA 때와 달리(그때는 "지지점이 기존 정점과 중복이면 다음 후보로" 방식으로 해결됨) MPR의 포탈 정제 구조에서는 같은 방식의 보정이 이 사이클 시간 내에 완전히 해결되지 않아, 이번 사이클은 전략 문서에 명시된 Sphere/AABB 범위로 검증을 한정하고 이 한계를 기록만 해둔다 — 참고용/낮은 우선순위 모듈이라 추가 조사는 다음 사이클로 미룬다([DEFERRED]).
