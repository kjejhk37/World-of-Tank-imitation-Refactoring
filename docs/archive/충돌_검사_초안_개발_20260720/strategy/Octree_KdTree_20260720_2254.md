# Strategy: Octree / k-d Tree (로드맵 7번, 참고용 낮은 우선순위)

브레인스토밍에서 "Voxel과 목적 중복 커서 참고용, 낮은 우선순위"로 분류된 항목 — BVH/R-Tree/Voxel만큼 폭넓은 테스트 커버리지를 들이지 않고, 각 알고리즘의 핵심 차별점(분할 정책)을 정확히 구현하는 데 집중한다.

## 적용 방식

두 개의 독립된 작은 클래스. `GetBounds()`만 사용, 다른 알고리즘 모듈(BVH 포함)을 참조하지 않는다.

### Octree (`src/collision/octree/Octree.h`/`.cpp`)

- Voxel(균일 격자)과의 차이: 적응형 8분할 트리라는 점. 객체는 "완전히 들어맞는 가장 깊은 자식"에 배치하고, 어느 자식에도 완전히 들어맞지 않으면(중심을 걸침) 현재 노드에 남긴다(멀티 노드 등록 없이 정확성 보장).
- 노드당 4개 초과 시 8분할(고정 `maxDepth`까지). 단순화: 분할 시점 이전에 이미 저장된 객체는 재분배하지 않는다(정확성에는 영향 없음, 트리 품질에만 영향 — 참고용 모듈이라 허용).
- 쿼리: 각 노드에서 (a) 노드 자신에 저장된 객체끼리 브루트포스, (b) 노드 객체 대 모든 자손 서브트리 객체, (c) 각 자식에 대해 재귀. 세 경우가 정확히 한 번씩만 겹쳐 중복/누락이 없다.

### k-d Tree (`src/collision/kdtree/KdTree.h`/`.cpp`)

- BVH와의 차이: BVH는 매번 "가장 넓은 축"을 고르는 반면, k-d Tree는 이름 그대로 깊이에 따라 축을 순환(depth%3)하며 그 축의 중심점 중앙값으로 이진 분할한다 — 이것이 유일한 정책 차이이고, 트리 형태 자체(이진 트리 + self-collide)는 BVH와 동일한 패턴이라 별도로(독립적으로) 구현한다.
- 쿼리는 BVH와 동일한 self-collide 패턴(리프-리프는 `Intersects(AABB,AABB)`로 최종 확인)이지만 코드는 BVH를 include하지 않고 이 모듈 안에 독립적으로 새로 작성한다(요구사항 1).
