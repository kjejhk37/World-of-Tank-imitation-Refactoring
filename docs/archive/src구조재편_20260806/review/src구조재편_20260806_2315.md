# Code Review: src 구조 재편 (app → projects, platform/graphics 분리)

이번 리뷰의 주요 쟁점은 사용자 요청대로 **"폴더 구분 철학(platform/graphics/projects)을 실제로 지켰는가"**다.
`docs/architecture/platform_graphics_projects.md`의 판단 기준(핵심 질문, 메커니즘 vs 스키마 구분)으로 이동된 코드 전체를 재검사했다.

## Stage 1 — 검사 결과

### 의존 방향 검증 (grep 기반, 전수 검사)

- `src/platform/**`가 `graphics/` 또는 `projects/`를 include하는 지점: **0건**.
- `src/graphics/**`가 `projects/`를 include하는 지점: **0건**.
- `platform_lib`가 `graphics_lib`/`app_lib`를 `target_link_libraries`로 참조하는 지점: **0건**.

빌드 타겟 수준(링크 시점)과 소스 수준(include 시점) 양쪽에서 의존 방향이 `platform ← graphics ← projects`로 일관되게 지켜짐을 확인했다.

### 발견된 철학 위반 (전부 즉시 해소 가능한 크기라 바로 수정함)

- [HIGH] `platform/logging`의 `Log::Error`/`Logger::Error`가 파라미터 타입으로 `ErrorCode`를 직접 받고 있었다.
  - `ErrorCode`는 `LaunchConfigParseFailed`(projects/config), `UnknownRendererBackend`(graphics), `EngineWorkerStartFailed`(projects/engine) 등 이 애플리케이션 고유의 에러 카탈로그다.
  - `AppConfig`/`PlayerProgress`와 동일한 "메커니즘 vs 스키마 인스턴스" 패턴을 놓친 사례 — `renderer/config를 include하는가`라는 검사만으로는 안 걸러지고, `Log`라는 범용 메커니즘의 시그니처 자체에 스며든 경우라 처음 검토 때 놓쳤다.
  - **[해결 방안]**
    - `Log::Error`/`Logger::Error`의 파라미터 타입을 `ErrorCode` → `int`로 좁힘.
    - `ErrorCode.h`를 `src/platform/logging/`에서 `src/projects/`로 이동.
    - `main.cpp` 4개 호출부에서 `static_cast<int>(ErrorCode::X)`로 변환해 전달.
    - `LogFormatter`는 애초에 `ErrorCode`를 몰랐으므로(기존 주석에도 명시) 추가 변경 불필요.
    - `LoggerTest`/`LogTest`는 platform 메커니즘 테스트이므로 `ErrorCode` 대신 리터럴 정수(`2001`, `3002`)를 사용하도록 갱신 — 오히려 새 시그니처와 더 일치하는 형태가 됨.
  - `[RESOLVED]`
- [MEDIUM] `platform/Win32Window.cpp`의 내부 Win32 window class 이름이 `L"WorldOfTankImitationWindowClass"`로 하드코딩되어 있었다.
  - 이 클래스 자신의 문서 주석은 "IRenderer를 전혀 알지 못하며... 재사용 가능하다"고 명시하는데, 내부 구현이 그 주장과 어긋남.
  - 공개 API(생성자의 `title` 매개변수, 실제 화면에 보이는 창 제목)에는 영향 없는 순수 OS 등록용 내부 식별자라 동작 변경 없이 고칠 수 있었다.
  - **[해결 방안]**: `kWindowClassName`을 `L"PlatformWin32WindowClass"`로 변경.
  - `[RESOLVED]`
- [LOW] `CMakeLists.txt`의 셰이더 경로 설명 주석이 이동 전 경로(`src/renderer/<backend>/...`)를 그대로 참조.
  - **[해결 방안]**: 주석을 `src/graphics/renderer/<backend>/...`로 갱신.
  - `[RESOLVED]`
- [LOW] `docs/algorithm/*.md`(9개 파일), `docs/dependency/*.md`(5개 파일) — 영구 보관되는 참조 문서 14개가 이동 전 `src/` 경로(예: `src/collision/gjk_epa/Gjk.cpp`)를 총 22곳에서 참조.
  - **[해결 방안]**: 동일한 매핑 규칙(`collision/` → `platform/collision/` 등)으로 22곳 전부 일괄 치환.
  - `[RESOLVED]`

### 이미 인지되고 수용된 리스크 (이번 리뷰의 새 발견 아님, 전략 문서에서 이미 결정됨 — 재기재만)

- STATIC 라이브러리 3단 체인의 PRIVATE 서드파티 링크 전파 — 실제 빌드로 검증 완료, 문제없이 동작함(전략 문서의 우려가 기우로 확인됨).
- include root 공유로 인해 CMake 타겟 분리가 "링크 시점 강제"이지 "include 시점 강제"는 아님 — Phase B(별도 저장소)에서만 완전히 해소됨. 지금은 grep 전수 검사로 대체 확인함(위 의존 방향 검증 참고).
- `tests/SaveLoadManagerTest.cpp`(platform 메커니즘 테스트)가 `PlayerProgress`(projects 예시 타입)를 테스트 더블로 빌려 씀 — 한 레포인 지금은 문제없음, Phase B에서 platform 자체 `ISaveable` 더블로 교체 필요.

### 표준 검사 항목 (SOLID / 라이브러리 격리 / 테스트 / 주석)

- SOLID: 이번 사이클은 구조 재편이 본질이라 SRP/DIP 위반을 오히려 2건(Win32Window, Log/Logger) 찾아 수정함 — 위 참고.
- 라이브러리 격리: 이번 재편으로 wrapper 클래스(TinyObjWrapper/UfbxWrapper/CgltfWrapper 등)의 배치나 역할은 바뀌지 않음 — 영향 없음.
- 단위 테스트: 기존 281개 테스트 전부 새 경로/시그니처에 맞춰 갱신 후 통과. 이번 사이클에서 새 기능은 추가하지 않아 신규 테스트는 불필요.
- 주석 규칙: `RendererFactory`/`Log`/`Logger` 등 시그니처가 바뀐 파일은 Notes에 변경 이유와 `docs/architecture/platform_graphics_projects.md` 참조를 추가함. 순수 이동만 된 파일은 기존 주석(Author/Description/Input/Output/Notes/Date) 그대로 유지.
