## 발견된 이슈

Code Review Stage 1에서 나온 1건은 이미 해결했다.

- [RESOLVED] `GameManager.cpp`의 `kPrototypeSceneKey`가 `constexpr`이 아니었다 — `main.cpp`의 기존 관례와 불일치.
  → 해결: `constexpr const char*`로 수정, 재빌드·재테스트 완료.

Refactor Inspection에서 나온 3건은 사용자가 지금 해결하기엔 시기상조라고 판단해 보류를 확정했다.

- [DEFERRED] `Scene`이 Entity 열거 목록(`m_entities`)과 실제 소유(`EntityManager`)를 별도 자료구조로 관리한다 — 향후 Entity 제거 기능이 생기면 두 자료구조가 어긋나 댕글링 포인터가 생길 수 있는 구조.
  → 보류 사유: 지금은 Entity 제거 기능 자체가 없어 발생하지 않는 문제. 미리 대비하면 YAGNI 위반.
- [DEFERRED] `TransformComponent`/`Scene`에 전용 단위 테스트가 없고 소비자 테스트로만 간접 검증된다.
  → 보류 사유: 이 프로젝트의 기존 테스트 관례(`ComponentBase`도 동일)와 일치하는 상태라, 관례를 바꿀지는 코드 문제가 아니라 정책 결정 사안.
- [DEFERRED] `GameManager`가 씬 키(`"Prototype"`) 하나를 생성자에 하드코딩한다 — 씬이 여러 개 필요해지면 재설계 필요.
  → 보류 사유: 이번 사이클 승인 범위(씬 전환·생명주기 뼈대) 밖의 확장 작업. 실제로 두 번째 씬이 필요해지는 사이클에서 다룬다.

세 건 모두 `docs/architecture/게임로직_구조_현황.md`에 다음 검토를 위한 참조로 정리해 두었다.
