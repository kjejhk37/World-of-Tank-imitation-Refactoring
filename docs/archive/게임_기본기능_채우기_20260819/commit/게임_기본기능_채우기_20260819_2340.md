# Commit Report: 게임 기본 기능 채우기 (IntroScene 4/5종 위젯)

## 결과 요약

전략 문서의 구현 체크리스트 전 항목 완료.
`graphics` 저장소에 `team_task_delegation`으로 두 차례 요청(위젯 5종 렌더링 계약 → `v0.1.0`, 텍스처 로딩 API → `v0.2.0`)해 응답을 받아 `src/graphics` submodule을 `v0.2.0`으로 갱신했다.
`src/projects/main.cpp`에 `IntroUi`/`BuildIntroUi()`를 새로 작성해 Label/Button/Progress/StringField/Image 5종 위젯 + `UiElementRegistry`를 렌더 스레드에서 직접 구성·등록하고, `renderer->SetUiElementRegistry(...)`로 연결했다.
`PrototypeScene`/`TestScene` 관련 코드를 전부 삭제하고 `IntroScene`(빈 뼈대)으로 교체, `GameManager`가 이를 유일한 씬으로 등록하도록 변경했다.
Code Review Stage 1(SOLID/라이브러리 격리/테스트/주석) + Stage 2(다이어그램)와 Refactor Inspection을 모두 수행했다 — 각 단계 상세는 `docs/review/게임_기본기능_채우기_20260819_2336.md` 참고.

**설계상 중요한 변경(브레인스토밍 당시엔 없었음)**: 원래 계획은 `WOTUiManager`를 `IntroScene`(engine 스레드)이 소유하는 것이었으나, `graphics` 응답을 코드 레벨로 검토하는 과정에서 `SetUiElementRegistry`로 등록된 registry가 렌더 스레드에서 `RenderAll()`로 호출된다는 걸 확인했다. `IntroScene`은 `GameManager`를 통해 engine 스레드에서 살기 때문에, 원래 계획대로면 두 스레드가 동시에 같은 ImGui 위젯 객체를 건드리는 데이터 레이스가 생겼다. 사용자 승인을 받아 위젯/registry를 `main.cpp`(렌더 스레드)가 직접 소유하는 구조로 전환했다 — `IntroScene`/`GameManager`/`SceneManager` 파이프라인과 완전히 분리.

빌드/테스트: `platform_lib`/`graphics_lib`/`app_lib`/`tests`/`main` 전체 빌드 통과, 하드웨어 종속(`DirectX*`/`ImGuiManager*`) 제외 279개 테스트 전부 통과. `main.exe --backend=dx11`을 3차례(리팩터 전/후 포함) 무크래시 실행 확인(메모리 안정 ~72MB).

## 발견된 이슈

Code Review Stage 1에서 나온 2건은 이미 해결했다.

- [RESOLVED] `IntroScene.h`의 클래스 주석이 최종 구현(위젯을 `main.cpp`가 렌더 스레드에서 관리)과 어긋나 있었다.
  → 해결: Description/Notes를 갱신해 엔진/렌더 스레드 분리 이유를 명시. 재빌드·재테스트 완료.
- [RESOLVED] `main()`이 "Intro UI 구성"과 "앱 부트스트랩"이라는 두 책임을 함께 지고 있었다(SRP).
  → 해결: `IntroUi` 구조체 + `BuildIntroUi(IRenderer&)`로 추출. 추출 과정에서 자기참조 구조(`registry`가 같은 구조체 내 위젯 주소를 참조)를 값 반환 대신 `std::unique_ptr<IntroUi>`(힙 배치)로 설계해, NRVO 미적용 시 발생할 수 있었던 잠재적 댕글링 포인터를 사전에 차단했다. 재빌드·재테스트·재실행 확인 완료.

Refactor Inspection에서 나온 2건은 이번 사이클 완료를 막을 정도는 아니라고 판단해 보류를 확정했다.

- [DEFERRED] `BuildIntroUi()`의 분기 로직(텍스처 로딩 성공/실패에 따라 `ImageUI` 등록 여부가 갈림)에 대응하는 단위 테스트가 없다.
  → 보류 사유: `main.cpp`는 원래 단위 테스트 대상이 아니었고, 검증하려면 fake `IRenderer` 구현체가 필요해 별도 작업이 된다. 필요해지면 새 task delegation으로 다룬다.
- [DEFERRED] `IntroScene`이 완전히 비어있어 engine 스레드 파이프라인이 항상 빈 `InstanceSnapshot`을 만들고, `DirectX11Renderer`의 기존 폴백 동작(빈 스냅샷이면 큐브 하나를 그림)이 Intro UI와 함께 화면에 보일 가능성이 있다.
  → 보류 사유: 코드 결함이 아니라 기존에 있던 폴백 동작이 새롭게 눈에 띈 것 — 실제로 화면에 뭐가 보이는지는 사용자의 시각 확인이 먼저 필요하고, 그 결과에 따라 후속 사이클에서 다룰지 결정한다.
